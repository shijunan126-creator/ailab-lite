# 单机体验、调度与可靠性代码审查

日期：2026-10-25。审查起点 `aadfa9a`，远端主线 `df30dd5`；修复代码基线 `869e06b27cb82cdf4a19225f5b9be9ec3a4026b2`。用户授权全库审查、修复、完整验证、提 PR 并合并，不包含重新部署。

## 目标与覆盖

当前目标是在单机约束下改善体验、调度、性能和可靠性，同时保留以后扩机的授权、账本、持久任务、文件交付与服务接口边界。没有按目标架构图补装 Higress 或引入多机调度。

本轮检查了以下代码边界：

- API：认证、权限、用户锁、调用账本/额度、Run 状态、checkpoint/attempt fence、事务 outbox/claim/ACK、定时与排队/插话、会话树/分页/搜索、文件版本/回收站、分享、品牌/模板、记忆与技能。
- Agent：并发池与 Chat 保留槽、取消/超时、模型流与计费、恢复后工具重放边界、上下文、预览/快照、受控下载与技能工具。
- Broker/Worker：租约 CAS/恢复/容量、传输上界、路径边界、预览保留槽、扫描重试、解析子进程、OCR/摘要、对象与流生命周期。
- Portal：代理/认证、SSE 重连、异步状态、会话分页与版本切换、预览、搜索、资料库、通知、排队及共享类型。
- 共享与交付：模型/迁移图、存储/队列适配器、指标/日志、依赖锁、部署脚本与 Kustomize、CI 选测和门禁、回归与 E2E 的隔离和清理。

采用静态追踪、失败回归、双库与真实 Redis、生产构建的五服务浏览器测试、EXPLAIN 和有界性能探针。静态素材/生成架构图不逐文件人工审查。由同一执行者审查、实现和复审，没有声称独立评审或证明不存在其他缺陷。

## 已修复的发现

### R01 / P1：恢复 checkpoint 可绕过工具执行前的 token 预算

模型响应与待执行工具先持久化，预算检查在其后；进程恰在这个窗口退出，恢复时 `pending` 非空，原有预算检查被跳过。失败回归直接观察到已达预算后仍执行 `build`。

现在在每次循环入口同时约束“新模型调用”和“恢复的待执行工具”。已经完成的纯文字回复仍可按原有软预算契约结束，已交付产物不重复执行。回归覆盖累计用量为 100/100、pending exec、无新模型调用/无执行/失败状态。

### R02 / P2：部门用量归属冻结得太晚

旧代码结算时读取用户当前部门，调用尚未结束就调部门会改变这笔历史用量的归属。现在在预留调用额度时冻结 `UsageReservation.dept_id`，正常结算、预留过期和晚到结算都沿用此值。

新增迁移 **0029 ← 0028**：已有账本行沿用已记录部门；没有历史证据的旧预留保持 null，不从当前用户部门猜测。双库检查升级、降级、再升级和数据保留；不重算旧账单或价格。

### R03 / P2：对话详情产生按轮次增长的查询往返

20 轮详情原本执行 **86 次读取**，其中逐轮查询产物、输入文件、调用用量和兄弟版本。现在按页批量读取，使用 SQL 聚合用量和窗口函数取得每个父节点的最多 50 个版本；相同直接路由夹具下是 **9 次读取**（前后均不含认证依赖）。

沿用既有 `run_id`、会话父节点与主键索引，无新索引/后台缓存/依赖。SQLite/PostgreSQL 均检查 EXPLAIN；PG 小夹具关闭 seqscan 的分项只证明索引可用，不能当作生产优化器必然选择该计划。

### R04 / P2：空 SSE 响应无限重连，等待累积 abort listener

原有次数上限只在 fetch 抛异常时生效；持续返回 HTTP 200 后立即 EOF 会无限请求。重连等待完成后也不移除 abort listener。

现在八次连续无进展后明确报错；收到新事件后仍重置预算。每次等待在完成/取消时移除 listener，保持事件游标去重与 reader 关闭语义。原生 Node 测试覆盖网络失败、空响应、事件重连和取消。

### R05 / P2：资料库扫描轮询重叠并可能回写旧状态

旧 `setInterval` 不等待上一请求，慢网络下每两秒新增一份请求；旧扫描快照可覆盖收藏、项目等新操作，甚至使已 ready 文件回到 pending。

现在一次请求完成后再排下一轮，每次 15 秒超时，卸载/筛选变化取消；只向仍 pending 的同一文件合并扫描状态与派生元数据，保留当前收藏/位置等字段。浏览器用可控时钟挂起响应十秒，检查始终只有一份在途请求，ready 后停止轮询。

### R06 / P2：版本切换存在旧分页与旧预览残留

版本切换/编辑时旧的“更早消息”请求仍可完成，把另一条路径的轮次混入。前端还把后端返回的完整路径预览清单与旧清单合并，导致被放弃分支的文件残留。

现在路径变更取消旧分页并清理其加载状态；旧响应被忽略。后端预览清单是完整路径快照，刷新时直接使用；本地流式预览在路径切换时清空。浏览器回归挂起旧分页、切换真实版本，再释放旧结果，确认新路径与继续分页保持正确。

### R07 / P2：有界搜索被误展示为“未找到”

API 每请求扫描有界，允许空页带续查游标。Portal 只自动续查六次便丢弃游标，较旧对话无法再找到；新查询等待期间仍能点击旧查询结果。

现在保留游标并提供“继续搜索”，每次交互仍最多六次有超时的请求；新查询清空旧结果。浏览器覆盖六次空页后第七次命中、新查询结果隔离、桌面/手机无横向溢出。没有把全量扫描搬到单次 API 请求。

### R08 / P2：累计插话超过五条后刷新丢展示

五条是尚未处理队列的容量，不是一个 Run 累计确认插话的上限。旧 serializer 截断 `steer_ids[:5]`，多批插话虽然进入模型与 checkpoint，刷新后只显示前五条。

现在按 checkpoint 的全部确认 ID 批量取回，保持确认顺序且不披露只领取、未确认的记录。修正原先把容量误当展示上限的测试，以六条已确认加一条未确认覆盖，并保留双库索引检查。

### R09 / P2：历史文件引用点开无反应

文件版本不可变，旧版本仍可下载；但 Portal 查看器通过 `/files?ids=` 获取元数据，该路径复用列表的 `is_head=1`，因此旧引用无匹配项。

现在显式 ID 查询解析对应的保留版本，常规浏览/搜索/项目列表仍只列最新版本；归属、library 用途、删除/清理过滤仍保留。回归同时验证普通列表不出现旧版、精确查找能返回旧版、删除后默认不可查，以及真实浏览器引用显示原文而非新版本。

## 性能与资源

本机 macOS 探针，不是 2 vCPU/8 GiB 目标机的容量验收：

- 20 轮详情读取由 86 次到 9 次，减少约 89.5% 往返；500 轮详情首屏 p95：SQLite **20.13ms**、PG16 **20.91ms**，各 25 次采样。不同运行的绝对耗时不用于声称等比例的延迟收益。
- 两个延迟 Work + 100 Chat 的调度替身测试：总活跃峰值 3，Chat 排队 p95 **33.66ms**，10.01 秒墙钟/0.75 秒 CPU；进程 RSS 高水位从 86.36 到 93.38 MiB。模型/沙箱并非真实负载，只验证调度及客户端开销；[数字](single-node-review-20261025/scheduler.json)。
- 0029 在隔离 SQLite 的 100,000 预留/50,000 历史账本上执行 **0.532 秒**，DB 41,676,800 → 44,093,440 字节；整段进程 RSS 高水位 **76.66 MiB**（包含导入与造数，非迁移独立增量）。历史查找使用 `ix_model_usage_call_id`；[数字](single-node-review-20261025/migration-100k.json)。PG 升降级已验证，未单独量测十万行 PG 迁移耗时。
- 无新增运行时依赖、服务、常驻后台任务或索引；新部门快照是每预留一列 nullable String(40)。迁移更新已有匹配行，会占用写事务；正式部署应按已有停写/备份流程另行验收。
- 搜索每交互最多六请求；扫描轮询每个可见视图最多一份在途请求，完成后间隔两秒；SSE 连续无进展最多八次。未用提高并发/内存上限掩盖问题。

## 保留的边界与优化顺序

没有证据要求把现有五服务改成其他框架。API 仍是唯一业务写入者；Agent 不取得数据库/容器运行时权限；Broker 保持单实例、Chat/Work 固定分槽与预览保留容量。动态借槽会影响 Chat 的等待保证，未在没有目标机混合负载证据时改变此契约。

后续最有价值的验收是目标单机的长时间真实混合任务：同时量测首字/排队 p95、解析/预览峰值、各进程 RSS、磁盘压力及取消后的收敛。浏览器大量已读历史缓存、单 Worker 下 OCR/摘要与扫描互相等待，可作为实测剖析对象；本轮未声称其最优，也没有在缺乏资源预算时新增并行解析线程。

本轮没有重复真实 Docker/OpenSandbox/gVisor、S3、ClamAV、Keycloak 或付费模型联合验收；这些未配置的外部契约跳过，不能由 mock E2E 推导通过。真实 S3 契约由远端 CI 单独执行。真机键盘、24 小时稳定性、硬件存储链路、生产规模灾备、HA/多机未验。

内置 preview 两次 snapshot 超时（原文 `Preview automation snapshot timed out after 15000ms.`），浏览器回归与视觉检查使用项目 Playwright 路线。个人配置、凭据、运行数据、日志及三份 `.DS_Store` 均不提交；E2E五服务及浏览器、内置preview tab、专用PG/Redis已停止，七个本轮端口无监听。Redis停止前核对pidfile与INFO process_id一致；没有停止已有服务。
