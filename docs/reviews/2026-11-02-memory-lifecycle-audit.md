## 结论与修复

| 触发 | 原因 / 影响 | 修复与回归 |
|---|---|---|
| 用户按摘要说“第二段” | 编辑只收到事实与指令，没有用户看到的摘要 | 请求携带显示文本，服务器校验它仍与当前摘要一致；在编辑任务中冻结摘要+事实。模型收到摘要、事实id、本次指令；提示词只允许按事实id修改，摘要只能定位，缺失/模糊时澄清。记录请求测试在 `test_prefix_cache.py`；摘要仍不进入主对话 bootstrap。 |
| 共享项目打开记忆 / 隔离编辑中途改共享再改回 | UI无模式分支，任务无项目模式围栏 | 共享只显示隔离开关，不挂载摘要组件，因此不加载/整理/轮询摘要；隔离才显示摘要、编辑、整理和清空。后端共享编辑409；开始/提交复核模式；改共享时取消旧编辑并清除claim，切回隔离不能重放旧指令。 |
| 清空当前为空的作用域 / 删除空项目 | 清理只依赖当前被删事实，未取消显式新增，也遗漏旧快照 | 按整个作用域清理 before/after、候选与交付副本、编辑摘要/指令；取消pending/running编辑，使清空先于模型返回也不能迟到新增。排队编辑另存事实digest，避免删除清理文字快照后反而通过旧快照比较。 |
| 不同项目保存相同文本后删除其中一份 | 历史副本按全文hash匹配，忽略作用域，导致其他项目的撤销/回放事实丢失 | 按id或 `(project_id, 内容hash)` 匹配；清空一作用域仍保留另一作用域同文本的快照。 |
| 编辑等待期间其他作用域/设置更新，然后撤销 | 编辑允许无关更新，但撤销快照来自模型等待之前 | 在最终提交前取当前文档为before快照，撤销只移除这次编辑效果，保留并发写入。已有scope-conflict回归补充撤销断言。 |

## 继续保持的契约

- 事实是可修改数据源，摘要是派生视图。普通对话拿有界事实，不接收页面摘要；本次只改变记忆编辑侧调用的payload，主循环系统消息、工具集合和历史前缀规则不变。
- shared→isolated：同事务迁移“证据非空且全来自本项目”的账号事实；手写/混合来源保留账号。isolated→shared：保留事实、后台融合，错误不部分提交，待融合标记重试；返回isolated取消待融合。此往返不是快照恢复，未改产品规则。
- 共享项目仍可保留项目专属事实（现有设计），本次隐藏其独立管理UI，不将所有项目事实自动变成账号事实。账号摘要和编辑只覆盖账号事实。
- 删除来源对话保留用户已保存事实，但移除引文、证据链接、episode/embedding及副本（既有用户决定）；删除事实/清空则清理删除谱系，不能用撤销复活。
- 撤销仍有revision围栏，不覆盖提交之后的新修改；事实批次/游标先提交，摘要刷新保留活动租约，崩溃不重放终态批次。
- 0046升级把旧project_only映射项目模式，降级以“存在任一隔离项目”恢复旧开关；摘要表降级可丢弃，事实和其他用户设置保留。不新增迁移。

## UI components 优化建议（本次未实施）

现有按需披露方向正确；全量回退与重复文档有改进空间。按现存消息中的版本化文档重建已知组件与指南，跨Run复用；同版本重复读取只返回简短“已在上下文中”和新增依赖。压缩/版本变化后按真实保留内容重新披露，不能只凭一个永久布尔标记。保持工具schema和旧消息不变，只追加结果。无工具模型优先Markdown；如要继续GenUI，明确固定精简静态子集，不能默默注入全部57份文档。改动需要录制请求与真实多轮缓存/语义验收，不能用字符数声称token收益。
