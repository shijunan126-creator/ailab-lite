## 一、最终行为

### 可见性、范围和来源

- 统一 `memory_recall/policy.py`：所有模型输入、工具 list/search/写返回/重放、nightly 使用同一套 suppressed/invalid/review/范围规则。管理页保留完整视图。恢复checkpoint或继续模型调用时重新校验记忆块及记忆工具/历史结果，避免沿用旧权限快照。
- 项目事实带 `project_id`，普通对话不读项目事实，项目间不能互相读取。账号偏好可用于项目；“项目仅使用本项目记忆”可排除账号事实。历史检索和原文读取也在查询/API边界约束项目及账号。
- 使用记忆是总开关；自动写入、引用历史、夜间整理分别控制。关闭自动写入后nightly不再抽取新事实。对话菜单可分别禁止读取已有记忆或将本对话用于记忆；新Run冻结禁止策略，之后重新开启不会把当时禁止的轮次追加入库。不是恢复被取消的“临时对话”入口，原对话仍按普通对话保存。
- 在线事实按问题词法相关度和偏好选择，最多20条、4000字符估算预算；仍受整体模型token预算约束。`memory search`支持显式 `as_of`；旧状态保留，可回答明确历史时间问题。`recall_history`可续扫最近400条之外的历史、限定时间并按run_id查看命中原文。
- 引文由服务端重新匹配到真正支持它的用户episode，模型提供的错误run/episode ID不能成为来源。独立judge增加事实支持度检查，遗漏/不确定结果拒收；助手推测、第三方假设不能仅凭相似文本变成已确认用户事实。敏感个人推断进入“确认使用”状态。
- Agent纠正追加新事实并链接旧状态，修复时不再把北京事实挂到旧上海证据。夜间新事实和全部失效操作是一组，变更预算不会拆开；晚到的旧事实不会覆盖更新的已确认状态。

### 后台处理、可靠性和成本

- 迁移0034增加持久工作项、候选/原文段落进度、后台claim/lease、对话记忆策略和账本job_id。SQLite只ADD/DROP列，不重建有引用的表；双库升级/降级/再升级及metadata drift验收。
- 不再用创建时间游标代替完成进度。预算之外的episode、候选、长消息尾部和已确认插话有明确的下一批；相同时间戳与晚完成Run也不会永久跳过。每批只处理一个项目，最多40轮，抽取输入按字符预算，judge与单次输出也有界。
- 固化episode和候选的短事务先结束，再等待模型；提交时在用户锁内复核claim、revision、来源可见性/范围、记忆开关与墓碑。真实SQLite第二session写入探针证明模型等待期间不再持全库写锁；并发派发只允许一个模型owner。
- 每次实际抽取/裁决都单独reserve/settle，冻结调用时部门、权重、折扣、策略，计入现有用户日/月额度；超额不发起模型请求。失败/取消保留账本估算或未结算保守预留，重试是新的call_id。离线抽取评估也走有身份的计费job，不再有隐藏免费路径。
- embedding SQL在LIMIT前过滤禁用账号，消除回填饿死；提交向量时与删除共用用户锁并重检来源。模型名、部署version和文档prefix进入索引版本指纹；同名模型升级时调整 `AILAB_MEMORY_EMBEDDING_VERSION` 即重建。错误响应、无效维度/NaN/重复index不能进入向量表，失败仍退回词法。

### 删除、撤销和界面

- 来源删除同步清episode/vector/待办及所有快照、计划、重放中的原话引用，并清除词法缓存。保存事实正文继续沿用ADR0019的独立删除语义，标记来源已删除；用户删除事实则清除所有派生副本，仅保留hash墓碑，后台不能复活。
- 整理撤销必须匹配整理后的revision，不能覆盖更新的用户编辑；旧快照也受删除传播约束。项目删除同时删除其专属事实，避免留下无法访问或无法保存的孤立范围。
- 记忆页提供账号/项目筛选、搜索、当前/历史、来源原话与原对话链接、敏感事实确认、暂停/恢复。模型返回的字段与页面改动保持向后兼容；关闭来源页或切换请求会取消/忽略旧响应。
- 整理后父页面自动读取最新事实；撤销采用页面确认而非浏览器原生dialog；后台详情与轮询取消旧请求。手机正文独占一行，控件不再把中文挤成竖列；浏览器有实际宽度及溢出断言。

## 三、失败历史与保留边界

- 初始旧断言假设全量事实常驻、replace覆盖旧id、预算丢弃旧episode，与新合同不符；现保留权限/幂等/过滤强断言并验证追加纠正、按需选择和不丢进度。
- 长插话探针最初因夹具缺model/误用input_file_ids而失败，修正为真实QueuedMessage字段后通过；未降低产品断言。首次完整SQLite是在新增索引实施期间运行，迁移metadata不一致及旧断言失败；修完后整套已通过，保留历史日志在本机，PR只携带可维护回归及最终证据。
- 测试Redis曾准备与另一套共用DB15，已在开始阶段中断PG套件并改独立DB14重跑；最终两套与浏览器分别使用独立DB，无开发库操作。
- 没有做付费模型、真实GPU embedding、S3/ClamAV/OpenSandbox/Kubernetes整栈新验收。相应外部合同按URL缺失跳过；远端CI继续检查双库、存储与浏览器。真实模型事实支持判断仍有误判概率，不能把有限测试称作“永不出错”。
- 保留100条/12000正文字符的事实容量；满时明确报错和保留待处理候选，不静默丢掉活跃事实或历史。原始历史单次400条可续页，正文详情仍有明确大小限制。未恢复已取消的临时会话，不扩大到共享账号、跨租户多主体图谱或新数据库服务。
