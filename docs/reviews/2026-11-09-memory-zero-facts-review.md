# 记忆“零条”与历史引用审查（2026-11-09）

基线：部署 `release-e47d22d` = `origin/main@e47d22d`；`memory_dream/`、`memory_recall/search.py|text.py` 与本检出 `c033664` 相同。只读查询本机库与代码，未改产品代码、未调用模型。

## 结论

管线没有坏：主账号 123 个成功 Run、108 个已处理，25 次整理全部 `applied`，但几乎每次抽取只返回 `{"facts":[]}`（completion 5 tokens）。零条是**抽取策略**的必然结果，不是故障。

- 用户消息几乎都是信息查询（公司业绩、电影、汽车、AI 模型）和开发测试指令，没有“我是…”“以后都…”这类自述。`EXTRACT_SYSTEM` 明确规定“询问的话题不是用户事实”“不得从重复行为推断偏好”，所以按规则就该是空。
- 10-30 的宽松版本曾抽出“用户关注英特尔过去24小时新闻”一类低质事实，后被删除并收紧提示词；现在从“噪声多”摆到了“永远为空”。
- 每批只放约 4 个 Run（每条带 1500 字助手回复，含 openui DSL），整理窗口看不到跨对话重复，结构上就不可能学到“经常要求可视化”这类真实偏好。每批 4–5k 输入 token 只为约 100 字用户原话。

## 缺陷

| # | 位置 | 问题 | 证据 |
|---|---|---|---|
| 1 | `memory_recall/text.py` `_CUES` | 英文提示词没有词边界，从单词内部删字 | `weekly→ekly`、`power→po`、`youtube→tube`、`answer→ans`；真实库查 “weekly report” 只剩 `report` 噪声命中 |
| 2 | 同上 | 中文“我/你”从词内删除 | `我国经济→国经,经济` |
| 3 | `process_dream` | 项目弹窗“立即整理”传入的 `project_id` 不参与选 Run，按最早 Run 的项目处理 | `service.py` `project_id = run_project(db, runs[0])` |
| 4 | `memory-summary.tsx` | 整理完成但新增 0 条时没有任何反馈，仍显示“还没有记忆” | 用户反馈 |
| 5 | `recall_history` | 必须带 query，无法回答“最近/上周聊了什么” | `tools.py` 无 query 报错 |
| 6 | `_extract` | `scope` 只追加在提示词末尾，不在 JSON 示例中；缺省落项目 | 次要 |

生命周期、删除谱系、墓碑、计费与围栏部分沿用 10-28/11-02 审查结论，本次未发现新问题。

## 推荐方案（未实施）

1. **两层记忆**：保留现有“明确自述/明确长期偏好”层；新增“推断画像”层，由程序校验至少 3 个不同对话、2 个本地日期的用户原话引文，标注为推断、在管理页可见可删，提示词中权重低于明确记忆；排除测试/调试指令。
2. **整理输入**：助手回复截到约 300 字并去掉代码围栏/openui，单批 20–30 个 Run，减少调用次数与 token。
3. **一次性回补**：策略上线后对已 `done` 且无候选的 Run 有界重扫一次。
4. **立即整理**：按传入作用域选 Run；完成后显示“看了 N 段对话，没有需要长期记住的内容”。
5. **历史引用**：修 #1/#2（英文用 `\b`，中文代词只去独立词）；`recall_history` 允许只给 `before/after` 按时间浏览。dense 通道保持关闭（2 vCPU 预算）。
