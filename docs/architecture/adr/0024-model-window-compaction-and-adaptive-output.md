# ADR 0024 · 模型完整窗口85%压缩与动态输出预算

状态：2026-10-29用户明确选择，已本机实现/部署；不代表远端合并或满窗口容量验收。

## 决定与口径

用户确认按**模型配置的完整上下文窗口85%**触发压缩，允许本次输出上限随剩余空间动态缩减。旧`min(70%窗口, 窗口-模型最大输出)`的输入预算会在85%以前拒绝请求，因此一并移除该固定比例和按最大输出预留的算法；不能只把界面数值改成85%。

- `C`：当前实际调用模型的服务端catalog `context_tokens`，不按模型名字猜窗口。
- `T = floor(C × threshold_ratio)`；默认及本机当前设置为0.85，自动压缩默认开启。仍保留平台管理员原有可配置比例/开关，已有显式存储值不靠读时偷偷重写；本机通过管理API显式保存开启/0.85。
- `I`：当前请求的系统/历史/摘要/当前消息/工具/图像等经校准估算的总输入token。正常请求可用输入硬上限为`C-1`，至少保留一个输出token；`I`超过硬上限明确拒绝，不静默截断。
- 本次输出上限为`min(模型最大输出, C-I, 管理员单次上限（如设置）, 本次显式输出上限（如设置）)`，quiet调用另受已有2048上限约束。同一个最终值用于ModelCall、用量预留与实际provider请求；回退模型按自己的C和输出能力重新计算。

85%是**对可压缩上下文的触发阈值**，不是强行缩写当前附件或用户输入的许可。Chat与Work共享会话历史组装阈值；Work单轮累计工具记录也用同一函数判断，替换旧可用输入预算65%规则。达到阈值（包含相等）才触发相应整理，切换模型/有效窗口变化后重新计算。

## 摘要与恢复

摘要请求同样占用模型窗口。历史压缩按摘要模型自己的窗口，为`min(2048,该模型最大输出)`保留空间后再打包旧摘要与新增历史；Work增量压缩同样保留摘要输出空间。这是在构建一次摘要请求，不是提前压缩主请求或把正常回复固定在2048。

保留既有增量消费游标、来源、原文件、最近完整assistant/tool组和确认副作用合同。Work checkpoint额外保存当前有效threshold，非收敛检查比较同一阈值，避免旧70%/65%状态或模型变化导致错误暂停。可压缩部分无法收敛时保留进度并明确暂停，不循环重复付费；没有可压缩历史时不伪造摘要，也不默默删当前输入，最终硬预算仍校验。

无业务表变更/迁移；API仍是唯一业务DB writer。现有事务、模型调用入账/结算和服务授权边界不变，不引入跨模型等待的事务/锁。

## 保持的边界与代价

文件50MiB上传/20MiB默认解析、Chat单文件20万字符/整组附件准入和按需Work读取规则没有因本ADR取消。调整阈值不会把新附件自动摘要成“已读全文”。每请求仍按真实模型输出能力和管理员限制取最小值，不扩大供应商能力。

估算有误差；服务端catalog窗口须正确配置并通过既有重载流程生效。85%按配置计算，不代表真实供应商窗口已填满验证。较晚压缩允许更大的输入，可能增加单次延迟、用量和内存；不能只因摘要次数减少就宣称总体更省。此次仅分配计算和少量checkpoint元数据，没有新依赖或额外模型调用类型。
