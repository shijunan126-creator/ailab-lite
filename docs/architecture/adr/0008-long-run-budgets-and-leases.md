# ADR 0008 · Long Run budgets and renewable ownership

Status: implemented locally (2026-10-25); extends [ADR 0004](0004-self-developed-runtime.md). Validation and remaining boundaries: [long Runs](../../progress/updates/2026-10-25-long-runs.md) and [sources integration](../../progress/updates/2026-10-25-long-runs-sources.md).

## Decision

Cost, liveness and useful working time have separate bounds. Keep the cumulative 2M raw-token Run ceiling and user weighted quota; increase the step runaway backstop to 300 per continuation. A long task does not get an unrestricted spending allowance. 2M supports at most about 6,667 average prompt+completion tokens over 300 calls, less when reviews/summaries/retries consume calls. 300 is a safety ceiling, not a promise to fund 300 full context windows. Current-Run context compaction at 65% of model input capacity complements historical-turn compaction; summary inference is metered normally. Preserve the original input and two complete recent assistant/tool groups; the execution log and plan remain authoritative.

A Run job has a 300-second claim. The Agent renews it every min(60, lease/3) seconds through service-scoped, token-and-expiry-fenced POST `/internal/jobs/{id}/renew`. Renewal updates the same indexed outbox row and its dispatch eligibility. It cannot resurrect expired ownership. Transient renewal failures retry with exponential backoff (15/30/60 seconds at the default lease) and a per-call total timeout of at most 10 seconds. Only a confirmed renew extends the local ownership deadline, conservatively measured from request start. A 409 stale claim cancels work immediately; continuous failure stops work at lease minus min(30 seconds, lease/5), retaining the durable job for recovery. The initial deadline starts before the claim request, so claim response latency never grants extra ownership time. Queue visibility uses the lease duration; production execution uses the durable claim rather than a second duration lock. Transport duplicates during long work are harmless; the durable dispatcher republishes an expired claim at its next tick. Recovery is approximately one lease plus dispatcher cadence, independent of Run age. A continuation always has a new job identity.

The checkpoint stores monotonic active seconds, the next informational self-check and start step under that job identity. Old `review_at`, `review_progress` and `progress_marks` fields are discarded when restoring v1 checkpoints; unknown legacy budget environment variables are ignored by Settings (`extra="ignore"`). Crash recovery preserves this window; manual resume/answer creates a fresh time/step window. Sandbox admission waits are excluded; waiting_user/interrupted do not hold an executing Agent. Crash downtime is not charged to active work; time since the last persisted checkpoint can be undercounted. `work_ms` remains the existing user-visible cumulative RUNNING timer (including admission); it is not reset by continuation.

Every hour of active work, the model receives an informational self-check note. It does not grant an extension, gate progress or emit an event. Repeated writes or plan oscillation cannot buy more time. At 4h active work, send a wrap-up note and allow up to three further model steps, then pause. This is bounded graceful wind-down at a step boundary rather than a mid-model-call kill. Bounded model/finalization calls can exceed the threshold. The 300-step backstop adds one tools-disabled summary call. Then stop tracked commands, deliver leftovers, force a workspace snapshot/checkpoint and pause as interrupted without auto-resume. A 20-minute lack of successful event/model/tool progress cancels the await and takes the same pause path. Model calls keep their own deadlines; exec yields within 120 seconds and waits within 300 seconds. Config still requires the stall interval to exceed existing single-call bounds. Platform notes wait for pending assistant/tool groups to be paired.

A pure detector reads the durable tool log since the latest real user continuation/steer, separately from compacted model context. Identical call plus result four times, the same call failing three times (even with different error text), or six complete alternating A/B cycles produces one Chinese platform nudge and `agent.budget {kind:"nudge",reason}`. If repetition continues after that checkpointed nudge, pause with `run.error="检测到重复操作，已暂停，可继续"`. Call arguments and results are recursively canonicalized; durations, idle time and timestamps do not defeat comparison. Output tails and cumulative bytes remain significant, so advancing exec polls are not loops. The nudge is durable across crashes; actual user input resets its window. This is a bounded syntactic detector, not proof of semantic usefulness. Only the last twelve observations are hashed; selecting them sorts durable invocation keys and does not query the database.

Budget pauses are not FAILED. Real execution/configuration failures retain FAILED. Cumulative token exhaustion also pauses, but the resume endpoint rejects another same-Run attempt when its token ceiling is exhausted; the user must start a new task subject to quota. Time/step pauses can repeat without a fixed continuation count while cumulative tokens, user quotas, admission and checkpoint retention permit it. No pause automatically resets cost.

User daily/monthly weighted-quota refusal at model reservation also pauses manually, before model retry/fallback accounting, and never delivers leftovers. It writes `result.pause={kind:"quota",window,resets_at}`; continuation and every non-quota pause clear it. Admission still returns structured quota 429. The interrupted-run cancellation grace starts no earlier than the quota reset, so a monthly reset cannot cancel the run before it becomes eligible. Workspace GC preserves the exact checkpoint snapshot of a live Run, using one bounded primary-key lookup per object page; superseded and terminal snapshots keep the existing object-age TTL. Details and validation: [quota pauses](../../progress/updates/2026-10-25-quota-pause.md).

All `exec` calls use one mechanism: the existing Broker exec privilege starts a detached stdlib Python supervisor inside the sandbox and waits in the same Broker request. `yield_seconds` is 1–120 (default 30); the accepted `timeout_seconds` alias has the same meaning. Legacy `background:true` yields immediately. Commands that finish return the existing `{ok,stdout,stderr,exit_code,duration_ms}` shape with separate streams. Commands still running return `{ok:true,running:true,handle,output_tail,total_bytes,idle_seconds,exit_code:null,error:"",truncated,hint}`. `exec_wait(handle,seconds=30,offset=0)` waits 0–300 seconds, returns early on exit and reports the same observation shape; completion has `running:false` and an integer `exit_code`. `ok` on wait/kill means the handle status is known; the command's success is given by `exit_code`. `exec_kill(handle)` kills the process group and is idempotent while retained. Start remains non-replayable; wait/kill may replay. Missing/restored handles require inspecting saved files before restart.

Controls/logs live in `/tmp/ailab-background`, outside workspace snapshots, with Linux /proc process-start identity fencing. Mock providers translate that directory per sandbox. At most eight retained handles are allowed by default; at capacity prune oldest exited/stale handles first, preserve recent handles where space allows, and never kill an active command to admit another. Reject when all slots are active. Each command has a 1MiB ring log, 4KB incremental output tail and bounded 4K-character prefixes per stdout/stderr for immediate completion. Internal provider response transport is capped at 64K characters (formerly 8K), so escaped control JSON survives; model-visible output limits do not grow. The supervisor's expiry includes control/startup time and cannot exceed the remaining hard Run window at invocation. Pause/completion kill tracked commands before final snapshot, and real sandbox release destroys any remaining processes.

## V2 amendment (2026-10-25)

The v1 progress-gated extension was heavier than the underlying safety need: writing the same file under a new content hash could look like progress, while a looping model kept the liveness watchdog alive. Remove `run_soft_budget_seconds`, `run_review_interval_seconds`, progress marks and `soft`/`extended` events. Cost, step, hard-cap and liveness bounds remain independent. The hard 4h capacity ceiling deliberately remains for the shared 2-vCPU host; an hourly note is sufficient for reviewing direction.

The design follows the unified yielding execution mechanism in [Codex unified_exec](https://github.com/openai/codex/tree/main/codex-rs/core/src/unified_exec), and the event-window repetition detection / soft terminal waits in [OpenHands stuck_detector.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/stuck_detector.py), [local_conversation.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py) and [terminal tools](https://github.com/OpenHands/software-agent-sdk/tree/main/openhands-tools/openhands/tools/terminal). These are design references, not dependencies or claims that their current limits equal ours. A model no longer predicts whether a build will be short or long; it observes progress and waits. Only `agent.budget.kind ∈ {nudge,wrap_up,paused}` remains.

## Cost and boundaries

No schema migration, new service or package dependency. Default claim renewal remains one indexed single-row UPDATE per minute per executing Run, plus existing sandbox renewal/status polling. WorkBudget is O(1); the detector hashes at most twelve observations after sorting durable invocation keys. Durable arguments are retained beside results, so checkpoint size grows with tool input; cumulative tokens/steps still bound work and user continuation does not reset token spend. Each active command adds one small Python supervisor, at most eight, plus its own CPU/RSS inside existing sandbox limits. Ring logs total at most 8MiB by default, plus bounded stream prefixes/exit metadata (roughly 32KiB per handle for UTF-8 prefixes). The internal 64K transport increases a worst-case response by at most 56K characters; the model still receives bounded outputs. Short commands need one Broker round-trip, with helper startup and exit polling overhead (up to 250ms per poll), rather than an extra model turn. Host measurements and unverified Linux/provider/target-host boundaries belong in the v2 validation section of the [integration record](../../progress/updates/2026-10-25-long-runs-sources.md).
