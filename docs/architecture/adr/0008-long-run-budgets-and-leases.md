# ADR 0008 · Long Run budgets and renewable ownership

Status: implemented locally (2026-10-25); extends [ADR 0004](0004-self-developed-runtime.md). Validation and remaining boundaries: [long Runs](../../progress/updates/2026-10-25-long-runs.md) and [sources integration](../../progress/updates/2026-10-25-long-runs-sources.md).

## Decision

Cost, liveness and useful working time have separate bounds. Keep the cumulative 2M raw-token Run ceiling and user weighted quota; increase the step runaway backstop to 300 per continuation. A long task does not get an unrestricted spending allowance. 2M supports at most about 6,667 average prompt+completion tokens over 300 calls, less when reviews/summaries/retries consume calls. 300 is a safety ceiling, not a promise to fund 300 full context windows. Current-Run context compaction at 65% of model input capacity complements historical-turn compaction; summary inference is metered normally. Preserve the original input and two complete recent assistant/tool groups; the execution log and plan remain authoritative.

A Run job has a 300-second claim. The Agent renews it every min(60, lease/3) seconds through service-scoped, token-and-expiry-fenced POST `/internal/jobs/{id}/renew`. Renewal updates the same indexed outbox row and its dispatch eligibility. It cannot resurrect expired ownership. Transient renewal failures retry with exponential backoff (15/30/60 seconds at the default lease) and a per-call total timeout of at most 10 seconds. Only a confirmed renew extends the local ownership deadline, conservatively measured from request start. A 409 stale claim cancels work immediately; continuous failure stops work at lease minus min(30 seconds, lease/5), retaining the durable job for recovery. The initial deadline starts before the claim request, so claim response latency never grants extra ownership time. Queue visibility uses the lease duration; production execution uses the durable claim rather than a second duration lock. Transport duplicates during long work are harmless; the durable dispatcher republishes an expired claim at its next tick. Recovery is approximately one lease plus dispatcher cadence, independent of Run age. A continuation always has a new job identity.

The checkpoint stores monotonic active seconds, the next informational self-check and start step under an independent budget window identity. Old `review_at`, `review_progress` and `progress_marks` fields are discarded when restoring v1 checkpoints; unknown legacy budget environment variables are ignored by Settings (`extra="ignore"`). Crash recovery preserves this window. Only explicit user resume from budget/stall/loop/quota pauses creates a fresh time/step window; ask_user answers and automatic lease recovery retain it. Job identity still changes for every continuation. Sandbox admission waits are excluded; waiting_user/interrupted do not hold an executing Agent. Crash downtime is not charged to active work; time since the last persisted checkpoint can be undercounted. `work_ms` remains the existing user-visible cumulative RUNNING timer (including admission); it is not reset by continuation.

Every hour of active work, the model receives an informational self-check note. It does not grant an extension, gate progress or emit an event. Repeated writes or plan oscillation cannot buy more time. At 4h active work, send a wrap-up note and allow up to three further model steps, then pause. This is bounded graceful wind-down at a step boundary rather than a mid-model-call kill. Bounded model/finalization calls can exceed the threshold. The 300-step backstop adds one tools-disabled summary call. Then stop tracked commands, deliver leftovers, force a workspace snapshot/checkpoint and pause as interrupted without auto-resume. A 20-minute lack of successful event/model/tool progress cancels the await and takes the same pause path. Model calls keep their own deadlines; exec yields within 120 seconds and waits within 300 seconds. Config still requires the stall interval to exceed existing single-call bounds. Platform notes wait for pending assistant/tool groups to be paired.

A pure detector reads the durable tool log since the latest real user continuation/steer, separately from compacted model context. Identical call plus result four times, the same call failing three times (even with different error text), or six complete alternating A/B cycles produces one Chinese platform nudge and `agent.budget {kind:"nudge",reason}`. If repetition continues after that checkpointed nudge, pause with `run.error="检测到重复操作，已暂停，可继续"`. Call arguments and results are recursively canonicalized; durations, idle time and timestamps do not defeat comparison. Running exec_wait observations break repetition suffixes, including silent waits; finished waits still participate. Output tails and cumulative bytes remain significant for other observations. The nudge is durable across crashes; actual user input resets its window. This is a bounded syntactic detector, not proof of semantic usefulness. Each completed observation stores SHA256 fingerprints of normalized arguments/results and bounded bookkeeping instead of raw payloads; selecting the last twelve sorts durable invocation keys and does not query the database. Old raw-argument records migrate on restore, no-argument records are not assigned a synthetic identity, and pending results are retained whole until consumed.

Budget pauses are not FAILED. Real execution/configuration failures retain FAILED. Cumulative Run token exhaustion is FAILED with a clear Chinese instruction to start a new task subject to quota; preserve completed results and release the conversation. It cannot be an interrupted pause that admission will never resume. The existing failed-run contract pauses the inbox queue, which the user can explicitly resume into a new Run. Time/step pauses can repeat without a fixed continuation count while cumulative tokens, user quotas, admission and checkpoint retention permit it. No pause automatically resets cost.

User daily/monthly weighted-quota refusal at model reservation also pauses manually, before model retry/fallback accounting, and never delivers leftovers. It writes `result.pause={kind:"quota",window,resets_at}`; continuation and every non-quota pause clear it. Admission still returns structured quota 429. The interrupted-run cancellation grace starts no earlier than the quota reset, so a monthly reset cannot cancel the run before it becomes eligible. Workspace GC preserves the exact checkpoint snapshot of a live Run, using one bounded primary-key lookup per object page; Once a newer checkpoint commits, immediately attempt deletion of its superseded same-Run snapshot, backed by a transactional deletion intent. Terminal/orphan snapshots retain the object-age TTL fallback. Details and validation: [quota pauses](../../progress/updates/2026-10-25-quota-pause.md).

All `exec` calls use one mechanism: the existing Broker exec privilege starts a detached stdlib Python supervisor inside the sandbox and waits in the same Broker request. `yield_seconds` is 1–120 (default 30); the accepted `timeout_seconds` alias has the same meaning. Legacy `background:true` yields immediately. Commands that finish return the existing `{ok,stdout,stderr,exit_code,duration_ms}` shape with separate streams. Commands still running return `{ok:true,running:true,handle,output_tail,total_bytes,idle_seconds,exit_code:null,error:"",truncated,hint}`. `exec_wait(handle,seconds=30,offset=0)` waits 0–300 seconds, returns early on exit and reports the same observation shape; completion has `running:false` and an integer `exit_code`. `ok` on wait/kill means the handle status is known; the command's success is given by `exit_code`. `exec_kill(handle)` kills the process group and is idempotent while retained. Start remains non-replayable; wait/kill may replay. Missing/restored handles require inspecting saved files before restart.

Controls/logs live in `/tmp/ailab-background`, outside workspace snapshots, with Linux /proc process-start identity fencing. Mock providers translate that directory per sandbox. At most eight retained handles are allowed by default; at capacity prune oldest exited/stale handles first, preserve recent handles where space allows, and never kill an active command to admit another. Reject when all slots are active. Each command has a 1MiB ring log, 4KB incremental output tail and bounded 1000-character heads plus 8000-character tails per stdout/stderr for immediate completion, with the middle elided. Internal provider response transport is capped at 128000 characters; helper JSON uses ensure_ascii=False with a 120000-byte UTF-8 guard. Even two worst-case six-byte-escaped streams fit (about 108600 bytes plus fixed metadata). Agent tool_result exposes running, idle_seconds and up to 2000 characters of output_tail as stdout while running, without a handle. The supervisor's expiry includes control/startup time and cannot exceed the remaining hard Run window at invocation, except the three wrap-up steps get a fixed bounded 120-second exec lifetime. Pause/completion use one internal registry-wide kill control before final snapshot: the Agent list may contain already-pruned handles or be absent in old checkpoints, so neither its contents nor its existence may gate cleanup. Real sandbox release destroys any remaining processes.

## V2 amendment (2026-10-25)

The v1 progress-gated extension was heavier than the underlying safety need: writing the same file under a new content hash could look like progress, while a looping model kept the liveness watchdog alive. Remove `run_soft_budget_seconds`, `run_review_interval_seconds`, progress marks and `soft`/`extended` events. Cost, step, hard-cap and liveness bounds remain independent. The hard 4h capacity ceiling deliberately remains for the shared 2-vCPU host; an hourly note is sufficient for reviewing direction.

The design follows the unified yielding execution mechanism in [Codex unified_exec](https://github.com/openai/codex/tree/main/codex-rs/core/src/unified_exec), and the event-window repetition detection / soft terminal waits in [OpenHands stuck_detector.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/stuck_detector.py), [local_conversation.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py) and [terminal tools](https://github.com/OpenHands/software-agent-sdk/tree/main/openhands-tools/openhands/tools/terminal). These are design references, not dependencies or claims that their current limits equal ours. A model no longer predicts whether a build will be short or long; it observes progress and waits. Only `agent.budget.kind ∈ {nudge,wrap_up,paused}` remains.

## Cost and boundaries

No schema migration, new service or package dependency. Default claim renewal remains one indexed single-row UPDATE per minute per executing Run, plus existing sandbox renewal/status polling. WorkBudget is O(1); each completed tool hashes its current payload once, then the detector compares at most twelve fingerprint observations after sorting durable invocation keys. Each consumed result retains only bounded status/error/uncertain-execution bookkeeping and a completion marker, including small results. Pending results remain whole until consumed. Legacy pending results, confirmed deliveries, started non-replayable markers and model context retain their replay contracts. Cumulative tokens/steps still bound work and user continuation does not reset token spend. Each active command adds one small Python supervisor, at most eight, plus its own CPU/RSS inside existing sandbox limits. Ring logs total at most 8MiB by default, plus at most about 72KiB of retained Unicode head/tail text and 108.6KB of escaped exit metadata per handle (separate from command descendants and decoder chunks). The internal transport increases by at most 64000 characters from v2, while helper JSON is bounded to 120KB and model outputs remain bounded. Every pause/finish with a lease now needs one cleanup Broker request even when an old checkpoint has no handles. Short commands need one Broker exec plus one request-file put (and a helper install put once per lease), with helper startup and exit polling overhead (up to 250ms per poll), rather than an extra model turn. Host measurements and unverified Linux/provider/target-host boundaries belong in the v2 validation section of the [integration record](../../progress/updates/2026-10-25-long-runs-sources.md).

## Review 3 amendment (2026-10-25)

The independent review confirmed all twelve findings, including non-converging compaction and multi-window checkpoint growth. The [review 3 record](../../progress/updates/2026-10-25-long-runs-review3.md) owns per-finding evidence, final counts, costs and unavailable real-provider boundaries.

A lease-local detached parent reaps supervisors, and on Linux adopts orphan descendants with PR_SET_CHILD_SUBREAPER; it never delegates their ordinary completion to an unknown provider PID 1. Docker's expiry PID 1 also ignores SIGCHLD. Supervisors reset SIGCHLD to default before waiting for their own command. Linux Z state is dead; disappearance without an exit record becomes a known failed exit, never an indefinitely running handle. Registry cleanup is best-effort before pause/finish, with lease destruction as the final process boundary.

Install the hash-verified helper through put_file and move it outside workspace snapshots; read/delete each JSON payload file rather than inlining helper and escaped command into Broker's 20,000-character command budget. Preserve the original user command limit. Running wait observations do not create workspace snapshots; first completion does, and final cleanup snapshots unfinished background work. The original user-message index is computed after real history/context assembly, not on its discarded input list.

Record the post-compaction estimate. If the preserved input and recent tool groups still exceed the 65% threshold, pause before paying for another equivalent compaction. Size every checkpoint using the API's UTF-8 serialization rule independently of model token capacity. If it still cannot fit after consumed-log compaction, persist a bounded frozen checkpoint and pause clearly; recovery must never execute omitted pending/paid records. Preserve unfinished non-replayable started markers and available delivery identities. This is a capacity stop requiring a smaller/new task, not a claim of lossless continuation. A durable out_of_steps_done marker prevents another paid summary on same-window redelivery. A fully completed answer remains successful even when it crosses the time boundary.
