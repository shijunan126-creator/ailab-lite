# ADR 0030：模型请求前缀稳定（参考 DeepSeek Harness）

状态：部分被取代（2026-11-01，合并 `fix/prefix-cache-render` 时）。决定 2（历史按原文渲染 GenUI）保留。决定 1、3 与“压缩不复用主前缀”由[前缀缓存设计](../design/2026-10-31-prefix-cache.md)取代：所有窗口在一次运行内使用固定工具目录（小窗口用精简目录，不再逐步激活）；记忆等上下文留在边界 system 消息，运行中变化以追加消息表达，只在压缩/重建边界刷新；压缩摘要、收尾、监督检查与子任务都复用主请求的同形前缀。真实 DeepSeek 验收见 [dated update](../../progress/updates/2026-10-31-prefix-cache-render.md#修复后复测2026-11-01代码-da98cbe)。原文保留作历史。原状态：已采纳。修订 ADR 0023 中“模型初始工具只含入口”一条，以及“稳定系统段 + 动态项目/记忆段位于首两条消息”的布局；工具发现不是授权、执行期校验不变。

## 背景

用户反馈 2026-10-30 晚的测试对话前缀缓存命中可能异常。DeepSeek 等 OpenAI 兼容后端按“已见过的最长请求前缀”命中缓存，工具 schema 渲染在全部消息之前。用录制请求的测试工装（见 `tests/test_prefix_cache.py`）对比相邻两次模型请求，`main@f316b85` 有三处会让前缀断开：

1. **工具逐步激活**：`search_capabilities` 每激活/淘汰一个工具，`tools` 数组就变化，整段对话重新 prefill。Work 模式要先发现 exec/deliver_file，几乎每个任务至少一次。
2. **GenUI 只在最近一轮保留**：历史中只有最后一轮保留 openui 原文，更早的改为 `[界面：X]`；下一轮就改写了上上轮回复。API 分页上下文还按“每页最后一条”保留，页边界同样改写。
3. **会变的上下文在历史之前**：第二条 system 携带记忆条目、项目资料索引、本轮 PPT 模板和工作区过期提示；任何一项变化都使其后全部历史失效（DeepSeek 模板还会把所有 system 消息提到开头）。

## 参考：DeepSeek Harness（dsh 0.1.5-rc.1 源码）

会话是只追加的事件日志，请求必须可由日志逐字节重建；工具 schema 按名稳定排序，运行中不随发现变化，发现结果作为工具结果/消息追加；运行时上下文以末尾 user 消息追加，只在变化时追加新快照；压缩不覆盖系统段，摘要调用复用原前缀。

## 决定

1. **工具列表在一次运行内固定**：当完整工具目录不超过模型输入预算的 15% 时（DeepSeek 等大窗口模型），每一步都提供完整目录，`search_capabilities` 仍用于发现办公/个人技能；系统提示相应说明“工具已全部列出”。小窗口模型保留原渐进披露。判定只依赖模型，运行内稳定。成本：完整 Work 目录约 2.9k token（开启网页工具时更多），命中缓存后按缓存价计费。
2. **历史按模型原文渲染**：Agent 与 API（`/internal` 上下文、model-context 分页）都对每轮回复保留 GenUI 原文，仍受原有字符上限约束。
3. **每轮会变的上下文挂在本轮 user 消息上**：`<ailab_context>`（记忆块、项目资料索引、本轮模板、工作区过期）放在当前用户消息开头；第二条 system 只留项目说明与品牌。之后的轮次从数据库 prompt 重建该消息，不带旧上下文，因此记忆/资料变化只影响当轮。运行中的记忆刷新逻辑不变（只在条目被删除/收窄或规则变化时改写，以正确性优先），位置改为当轮 user 消息，兼容旧 checkpoint。mock 模型读取用户文字时去掉该块。

## 不做 / 后续

- 不为命中率保留已删除记忆或越权内容；删除记忆时的改写仍会失去当轮缓存。
- 上下文压缩仍用独立摘要模型与提示，不复用主前缀（dsh 的做法是摘要调用重放原前缀）；按实测再决定。
- 需在真实部署按 run 统计 `model_usage.cached_tokens / prompt_tokens` 验证；本 ADR 的证据是请求结构，不是供应商实测命中率。
