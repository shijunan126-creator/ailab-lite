# ADR 0031：Work 运行内的并行子任务（run_subtasks）

状态：已采纳（首版）。来源：DeepSeek《Super-agent 设计探索》第 2 节双层架构（Router/Worker）与 DeepSeek Harness 的 fork 子 agent。

## 背景

一次 Work 运行是单个 ReAct 循环：调研 4 个主题再做汇报时，四份调研只能串行，中间细节也全部堆在同一上下文。文章的消融实验表明：只给主会话一个“可委派”工具并靠提示词引导，模型经常不委派（中性提示 5 次 0 次委派）；靠系统结构才能稳定分工。完整的 Router/Worker、事件驱动和订阅直通属于常驻多信道 Agent 形态，与本平台“按对话发起 Run”的产品形态不同，本 ADR 只取其中可在单个 Run 内落地的部分。

## 决定

1. **工具 `run_subtasks(tasks[2..4])`，仅 Work 模式**。每个子任务在同一 Run、同一沙箱租约内并发运行，最多 `AILAB_SUBTASK_MAX_STEPS`（默认 20）步，返回 `{title,status: done|failed|incomplete,steps,report≤4000字}`，由主循环汇总、生成和交付。
2. **fork 前缀**：子任务请求 = 主循环最近一次请求的消息（截至发起本调用的 assistant 消息之前）+ 一条子任务说明，工具 schema 与主循环完全相同。供应商可直接命中主循环的前缀缓存，子任务也继承用户要求、附件与已读资料。
3. **工具限制在执行时生效**：子任务只能用沙箱（list/read/write/exec 系列）、资料读取、网页、图片搜索、历史召回；其余（交付、提问、计划、记忆、技能、再派子任务等）返回错误。不从 schema 删除，避免改变前缀。
4. **不与用户直接交互**：子任务模型调用以 quiet 方式计费（不流式输出到对话），只发 `agent.subtask` 开始/结束事件；取消、租约失效、预算暂停会取消所有子任务并照常向上抛出。
5. **恢复语义**：`run_subtasks` 按普通可重放工具处理；Agent 中途重启会整组重跑（子任务只写中间文件、不交付，重跑是安全的）。

## 不做 / 后续

- 不强制委派：结构上仍由主循环决定是否调用；系统提示给出适用条件。是否需要“主循环不执行、只分派”的强结构，待观察真实使用后再定。
- 子任务步骤不在 Portal 时间线逐条展示，只显示 run_subtasks 工具步骤；需要时再加 UI。
- 同一沙箱内文件冲突靠说明中的独立路径约定避免，不做锁。
- 成本：并发子任务会同时占用模型并发和沙箱 CPU；2 vCPU 机器上上限 4 个，每个子任务共享 Run 的 token/时间预算。
