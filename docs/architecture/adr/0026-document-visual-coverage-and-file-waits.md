# ADR 0026：办公内容覆盖与持久文件等待

状态：本地实施，验证结果见[本轮记录](../../progress/updates/2026-10-29-document-reading-reliability.md)。

## 决定

原生文字、OCR文字与视觉内容是三个不同的覆盖维度。PDF、DOCX、PPTX、XLSX的读取适配器输出结构化`has_text/visual`事实，manifest保存`quality/visual_units`；标题、空白说明、图片占位不能成为原生正文。PDF检查图片/绘图操作，Word检查正文嵌图及包内媒体/图表，PPT保留形状布局的视觉覆盖，Excel把绘图与单元格读取分开。未知旧格式保守标为视觉覆盖未知，不冒充已看图。

Chat先完成正文及所选模型需要的视觉页面准备和预算准入；视觉模型在首个请求收到正文与页面，页面不可读时整轮失败，不静默少发。当前一个完整Chat包最多20个视觉页面，超过或超预算明确要求选范围/Work，不能只送第一页；这个资源边界不影响Work按批读取，也不是输入框五张独立图片的限制。非视觉模型可读取原生/OCR文字，显式说明不包含图片语义；纯视觉且没有可用文字的文件拒绝本轮Chat并提示选择视觉模型。没有自动换模型、没有把OCR当作架构图/照片理解器。

Work先提供精确附件身份、正文读取、OCR、视觉查看工具；模型按任务读取正文、选择视觉页。页面渲染走Broker系统沙箱，四种格式共用平台通道，无需为看图交付中间文件。Word/Excel的渲染页不等于原生段落/单元格锚点。工具返回截断、页数和定位类型，不能丢掉覆盖信息。

OCR请求按不可变文件、页范围、引擎指纹复用已完成结果；在途任务不能因查询被替换。完成后直接返回可读正文，失败不被模型重复调用自动重置；用户显式提取允许重试。原生parser升级为`ailab2`，原生索引重新生成，已有OCR按引擎独立私有复制，不因parser升级重复推理。已保存的`ailab1`内部技能版本继续兼容；旧PDF空页占位仅在已知旧parser范围内兼容识别。

## 等待合同

`extract_text/view_attachment`返回pending时，Agent保留已经付费的pending工具及首次截止时间，保存checkpoint/已有工作区，释放租约与执行槽。API将Run置为`interrupted`并保存程序生成的`file_dependency`，其含义是自动准备附件；无该元数据的interrupted仍是原有手动暂停。暂停前写等待事件，不能在结束attempt后继续写受栅栏保护的事件。

OCR/页面完成事务内检查依赖并通过outbox派发新continuation；旧任务ACK不能删除新job。已有dispatcher每秒有界扫描最多100个interrupted Run（按status/id索引轮转），补偿完成早于暂停、重启和超时；扫描不调用模型，也不占用用户沙箱。文件完成路径按file引用索引有界唤醒，避免对含JSON列的整行做DISTINCT。

恢复前重查额度、并发、会话、来源和checkpoint；资源不足保留依赖退避，确定性不可恢复错误结束Run。取消/删除后的终态不能恢复。OCR超时写失败，权限/扫描前置条件失败不能被ACK后遗留pending；旧无扫描凭据的pending转为明确失败，不放宽扫描要求。

Portal将`result.file_wait`作为自动等待识别依据：保持SSE、发送互斥与停止入口，显示一个“正在准备附件”状态，不展示手动继续。其他暂停/额度/提问合同保持原有语义。

## 成本和边界

不增加常驻解析器、模型调用或依赖服务；新等待状态复用既有Run JSON、checkpoint、outbox和索引，无迁移。系统读取新增分阶段计时；没有以跨用户共享常驻解析进程换取未经验证的提速。Excel文字读取使用去除绘图部件的临时包，原文件不变，图形交由隔离渲染器；这会增加含图Excel的压缩/内存成本，样本资源数据见验证记录。

结构检测不能证明任意图形语义已理解；模型实际图像能力与答案质量仍须单独验收。外部对象损坏、依赖故障和资源边界必须给出明确失败，不能承诺所有文件永远成功。
