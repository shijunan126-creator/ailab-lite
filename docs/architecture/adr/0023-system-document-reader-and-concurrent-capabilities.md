# ADR 0023：平台文件读取执行边界与并发

状态：本地实现中，2026-10-29。用户已授权实施，未授权发布。取代早期“只设计”的本会话限制。

用户确认平台面向数百人同时使用；当前开发机不承担数百人容量验收。OCR先只计量，不计费、不设用户累计用量配额；字节、像素、超时和执行槽位仍属于故障隔离。

## 决策

ZCode Office Runtime是平台固定版本的读取引擎，不是独立业务服务，也不是每个用户可管理的skill。引擎在Broker创建的短生命周期系统render租约中运行；Worker只扫描、编排、校验/存储结果，API保有授权与数据库唯一写权。用户Work租约持有原文件供编辑，Chat不获得exec权限。专用`sbx-document-reader`镜像不包含桌面UI、OCR权重或开发测试依赖。

每任务文档会话、临时目录和结果命名空间独立，实际原文件绑定到API生成的任务身份。解析器全量加载行为没有因分页而改变，因此容器按内存/CPU/时限/磁盘准入，冷启动与排队计入延迟。没有静默回旧解析器路径。相同file版本读已有持久结果；重复上传只允许同owner安全复制至新file命名空间，复制发生在Worker、事务/用户锁之外，提交前复核来源。

模型初始工具只含入口；激活工具与内部skill固定版本保存checkpoint。`platform.*`与用户技能目录完全分离。文档读取结果保存精确file、派生版本、块digest和连续游标。工具发现不是授权：执行仍验证mode、模型能力、当前可用目录和激活集合。

## 数百人架构约束与当前限制

- Portal和Agent可以有多个进程；状态在API数据库、checkpoint、对象存储和持久队列。不能把进程内锁当多副本正确性条件。
- 多API使用PostgreSQL行锁/CAS；SQLite仅单API开发配置，不用于数百人正式部署。当前会话路径500轮产品上限仍在，不声称100k轮可直接聊天。
- Worker消费者可复制，任务由持久claim/ACK/outbox调度；按文件/任务身份防重复发布。单Worker消费线程不等于全平台只允许一份解析任务。
- Broker每个instance group只允许一个fenced owner，组内共享Redis租约与资源准入。扩容不能简单复制相同owner抢锁；多节点需按既有instance group/路由部署，当前未新增完整跨节点调度器，也未验收多Broker路由。后续扩机只替换部署/adapter，不绕过文件授权和账本。
- Runtime不存在跨用户全局DocumentOwner/path缓存；每个解析任务独立，持久缓存由平台file身份管理。资源不足排队/明确重试，不无限创建Node进程。
- OCR部署多个有界执行器副本，前置负载均衡/资源队列；单副本并发槽位是节点保护，不是用户配额。API进程内OCR槽位只保护本副本，真实后端session/provider和部署资源才是执行权威；未实测NPU或数百人并发。
- 删除先写epoch/失效墓碑并取消受影响活动任务，再由持久游标分批清理。新轮次绑定新的epoch，避免历史失效污染未来正常轮次。恢复旧备份开放访问前仍需要运维应用墓碑，当前无跨备份自动擦除保证。

当前开发验收只可声明双库合同、真实系统容器有限并发及浏览器行为；目标服务器吞吐、Chat排队TTFT、NPU30分钟负载和数百人容量必须另验。不得以测试数量代替这些边界。
