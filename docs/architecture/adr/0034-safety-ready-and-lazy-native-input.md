# ADR 0034：安全原件就绪与按需派生
状态：已采纳（2026-11-05）。

## 决定

新普通输入在API创建时记录`input_lifecycle=2`。Worker在安全扫描、受限类型/压缩包检查、摘要与大小核验后即可发布`FileStatus.READY`，此时native_text/page_images/ocr_text各自为absent。上传不提取正文、不复制派生缓存、不缩略图、不预热或租Office沙箱、不生成语义摘要。实际识别的格式由API校正MIME。模板/品牌/技能专用入口和用户成品保持各自必要流程。

既有无v2标记的排队任务沿原路径恢复；只有这些旧任务允许在扫描通过、解析尚未结束时预览。v2文件的scan clean本身不能绕过类型/完整性检查提前启动派生。不是把旧文件全部重新扫描或解析。

Work可立即取得安全原件；Chat发送和显式消费才请求持久native job，图片只有消费时准备所需表示。native失败不改变原件安全就绪状态，也不返回假空白。旧`read_library_file`可通过新增native-text文件依赖等待原生准备，已付费调用/原工具目录保持，恢复后追加真实结果。

Native每代只存manifest和规范UTF-8正文，索引用字节范围与逐块SHA256定位；Office仍承认首次整包解析成本，普通文本在Worker受限子进程内流式读取，超200000字符失败而非截断。源版本、job/attempt与完成请求指纹共同围栏发布；两个暂存资产与索引/元数据在同一业务事务发布。

容量迁移先持久增量回填。启动/周期维护只回收未发布的失败/崩溃写入，发布缓存的TTL回收须等全部生产writer记账和业务失效接通。正常失败由API确认未发布后立即删除暂存；响应丢失但已发布的资产不能当作失败清掉。不得把backfill_complete当作所有新旧生产路径已受容量控制的证明。

## 与旧合同的关系

取代 ADR 0026 中“文件安全可用依赖上传全文准备”的旧实现含义；保留权限、来源、旧工具等待与恢复合同。

## V2 目录接入边界

新目录用 API 拥有的 run 选项选择，旧 checkpoint 继续固定原 schema。原生读搜、导航与模式围栏已接通；V1 已由 [ADR 0042](0042-single-tool-catalog.md) 退役。按模式指南从 `build.py` 生成独立 Agent 资源，旧沙箱技能包不改，避免仅修改技能文案也使旧 run 包哈希失效。

## Work V2 接线

新 Work 由 API 选择 V2 目录并只交原件引用；受限工作区图片经当前租约准备，API 调用 OCR 执行器。operation/lane 持久记录身份、绝对预算和取消/回收围栏，正常 OCR 会话保持暖进程。


## 原生范围合同

V5 长 PDF 先 probe，指定范围才提取；真实页导航不依赖正文。范围缓存独立于基础索引指针，并绑定基础代际；Word/Excel 仍整包解析后选结构范围，报告完整来源成本。范围原生任务进入 render 持久槽，发布沿两对象容量/尝试围栏，文件等待只追加恢复结果。


## V2 输入装配

发送前准备使用持久发送身份并冻结整份 inline/按需策略；首个重型工作起点与 600 秒截止进入 Run/排队快照。正文总预算取 24K token 与 20% 模型输入预算较小者，文档 inline 图总计 8，导航全轮 2000 token；不按物理总页数准入、不隐式 OCR。
