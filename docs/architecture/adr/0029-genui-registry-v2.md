# ADR 0029：GenUI 组件目录 v2 与按需披露

状态：已采纳。设计见 [registry v2](../design/2026-10-30-genui-registry-v2.md)，取代 [ADR 0028](0028-generative-ui-openui.md) 中“目录 v1”与“提示词整段进系统提示”两条；0028 的传输、持久化、控件状态、HtmlArtifact 沙箱与复制/打印规则不变。

## 背景

- v1 只有 21 个组件。时间线、步骤、对比、排名、流程图、甘特、瀑布、漏斗等常见表达都只能用表格或文字硬拼。
- v1 的提示词整段放在系统提示里，约占 Chat 提示的 85%（5.6k token）。不出界面的问答也要带上这些内容，模型因此被带偏。
- P6 四轮真实评测的严格一致性停在 43–61%。主要失败是模型自己写出或算错派生结论（最高、增幅、占比、差值），加上位置参数记错。只追加提示词禁令，错误会转移到别处，不会消失。

## 决定

1. **目录 v2（`CATALOG_VERSION = 2`）**：57 个语义组件，分布局、文字、指标、图表、高级图表、过程、对比、图示与代码、交互、页面十组。仍只在 `components/genui/catalog/schema.ts` 定义。v1 契约文件删除，因为历史回答按测试版处理，不保留 v1 渲染兼容。
2. **参数约定**：
   - 主数据最多 4 个位置参数，其余放末尾 `opts` 对象。
   - 共享键为 `unit`、`decimals`、`tone`、`better`。
   - 一组事物用固定键的对象数组表示。
   - lang-core 只支持位置参数；对象字面量里的错键会被单独丢弃，不会让后面的数据错位。
3. **派生值由组件计算**（P6 的根因修复）：
   - Highlights 算最值、合计、均值、中位数、区间、首尾变化、最大增幅/降幅、占比。
   - Metric 由 `previous` 算变化率。
   - Ranking 排序，并列时名次相同。
   - Compare 按 `better` 标出每行最优。
   - Waterfall、Funnel、ShareBar、Pie、Dumbbell 分别算累计、转化、占比、差值。
   - 计算放在纯函数 `catalog/data.ts`，渲染、复制用的 Markdown 和评测检查器（`shapeOk`）共用这一份。
   - 提示词规则：模型只交原始数据，块外文字只做解释，不重复结论数字。
4. **按需披露**：
   - 系统提示只放索引（约 750 token）：何时用、何时不用界面，按类的组件名，以及决定回答对错的规则（数字和结论由界面给出、块外只解读、不做未要求的统计）。第五轮评测证明，这些规则放进指南（工具结果）后模型遵守得更差。
   - Agent 新增本地工具 `ui_components(names)`。它返回所点组件的签名、opts、规则和示例，并按 `needs` 展开依赖。
   - 指南（约 2,250 token）只在本 Run 第一次调用时附上，标记随 checkpoint 保存，上下文压缩后清除重发。
   - 只有模型同时声明 `genui` 和 `tools` 时才提供该工具。不支持工具的模型改发全量提示。
   - `ui_components` 常驻 discovery core；其它工具和技能沿用原有的 `search_capabilities` / `load_skill` 按需加载。
   - 实测系统提示：Chat 5,604 → 1,448 token，Work 6,307 → 2,150 token。
5. **渲染与降级**：
   - 每个组件都有错误边界，换新 props 时重置。
   - 求值后形状不对时显示“数据格式有误，无法显示”。
   - 未知组件在解析时丢弃，其余照常渲染。
   - 高级图表（7.5 KB gz）和图示（4.2 KB gz）单独懒加载，打印前预加载。
   - 所有图形自绘 SVG，颜色只取宿主 token，附读屏表格，复制时输出等价 Markdown。
6. **明确不做**：
   - 外链图片、视频、地图：CSP 与隐私限制，需要时用 HtmlArtifact。
   - 来源卡片：由引用体系负责。
   - 领域专用卡片：用 EntityCard 和 KeyValue 组合。
   - 追问按钮组：用 Button + `@ToAssistant`。
   - 独立 Sparkline：只作为 Metric 的 `trend`。

## 后果

- 新增组件的步骤：在 schema 中定义（含 group、notes、example），写渲染器与 `shapeOk`/Markdown 分支，运行 `npm run genui:prompt`。Agent 与解析核心都不用改。契约测试会逐字节比对生成文件，并检查索引覆盖全部组件。
- 同一 Run 内，模型多一次本地工具往返，没有模型外的网络开销。不出界面的回答不再携带 GenUI 说明。
- P6 是否达标以真实评测为准，见[评测报告](../../progress/updates/2026-10-30-genui-real-model-eval.md)。“组件替模型计算”只消除了计算错误这一类；挑错列、标签写错这类语义错误仍要靠评测发现。
