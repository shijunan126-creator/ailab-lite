# ADR 0037 · 记忆只有一种行：去掉受保护、待确认与暂停
状态：已采纳（2026-11-11）。修改 [ADR 0036](0036-memory-quality.md) 与 [ADR 0035](0035-memory-v2.md) 中“受保护行”“敏感待确认”“暂停”三处语义；文档结构、快照/失效通知、计费合同不变。

## 背景

ADR 0035/0036 按写入者区分行（explicit/edited/manual/chat 受保护，inferred 可整理），敏感内容只能 `review` 待用户“确认无误”，另有 `suppressed` 暂停。实际效果：用户添加或确认过的一行，之后的对话无法再概括或改写它；健康、信仰这类用户自己说出的情况要多点一次确认；页面多出“你添加的”“推断”“待确认”三种标签。用户能直接在记忆页编辑、删除，或用记忆页下方的对话框改记忆，这些区分只增加复杂度。

## 决定

- **一种行**。`memory_items.origin` 一律写 `memory`（列保留给旧行和旧客户端，输入的 origin 被忽略）；`status` 只有 `active` 与 `closed`。读取、渲染、页面和 API 输出都不再有 origin/status/review/暂停。
- **整理可改任何行**。Dreaming 的 update/merge/transition/delete 与容量淘汰对所有活动行一视同仁；日常批次的 delete 仍只接受 H（重复）或 I（错误，须附用户原话）。
- **不记什么由内容决定，不由状态决定**。健康、信仰、家庭等用户自己说出的情况照常记；身份证号、银行卡号（16–19 位）、密码/密钥等凭据在 `guard` 一处拒绝，整理、页面编辑和对话工具共用。
- **按新标准整理一次时可以拆分**。旧文档里一行混了两类（如兴趣行附带“偏好用图表呈现”）时，`{"op":"add","kind","content","from":["原行id"]}` 拆出新行，来源与项目标签取自原行；除拆分外不新增。标准写明一行只属于一个分类，由事实带来的做法写成偏好行。
- **用户删过的内容仍不自动重学**（墓碑不变）；工具 `explicit=true` 只表示“用户明确要求”：允许在自动保存关闭时写入、覆盖墓碑、只在明确要求时 remove。
- 提示词与渲染格式变化使上下文 ABI 升到 **7**，`PROMPT_VERSION=2026-11-11` 触发一次按新标准的整理。

## 迁移 0069

当前行（active/review/suppressed）的 origin 改为 `memory`；review/暂停行改为 active，其中含证件号、卡号、凭据的关闭为 `deleted`，与活动行重复的关闭为 `condense`（保持活动唯一索引）。改动的行在 `metadata.origin_0069/status_0069` 记录原值，降级只恢复这些行；判定规则冻结在迁移内。已关闭的历史行保持原样。

## 后果

- 模型调用次数不变；系统提示略增（几十字），跨用户共享前缀。已打开的会话遇到一次 `context_abi_changed` 边界。
- 风险：模型推断错的内容直接生效。缓解：页面编辑/对话框修改、删除即墓碑；日常整理不能无引文删除或改写用户的话。
- 部署：一个迁移；API、Agent、Worker、Portal 同时更新。
