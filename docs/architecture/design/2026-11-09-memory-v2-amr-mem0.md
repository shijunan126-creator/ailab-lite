# 记忆 v2 实施方案：融合 Agent Memory Repo 与 mem0

- 状态：方案已确认，未实施。基线 `origin/main@e47d22d`（部署 `release-e47d22d`）。
- 问题证据：[零条审查](../../reviews/2026-11-09-memory-zero-facts-review.md)。
- 参考：AgentMemoryRepo `8798cb2`（MIT，规范与技能，无代码）；mem0 `f1791da`（Apache-2.0，v3 ADD-only 提取与混合打分）；Zep/Graphiti 双时间轴；Letta 记忆/对话双检索；Claude 历史对话工具的触发规则（第三方转录，未经官方核实）。

## 1. 目标与验收标准

现在全部事实每轮常驻系统提示，所以写入规则只能极严，主账号 123 轮对话得到 0 条记忆。v2 把“常驻”和“存量”分开：常驻很小，存量放宽收集，由模型按需查询。

成功标准（全部达到才算完成）：

1. 主账号历史回补后，记忆页能看到有意义的偏好、兴趣、项目与交付物；测试/复现类对话不产生记忆。
2. 触发评测：应查问题的查询率与不应查问题的克制率都达到第 13 节阈值。
3. 检索评测：Recall@5、MRR 达到阈值；无关查询返回“无相关记忆”。
4. 时效评测：偏好改变、计划过期、事实被纠正后只返回新值。
5. 删除/忘记、撤销、项目作用域、计费、围栏合同不退化。
6. 多轮 Chat/Work 前缀缓存命中率不低于现状（≥95% 目标不变）。
7. 几百用户的夜间整理在窗口内完成，且不挤占白天交互。

## 2. 总体结构

```
┌──────────── 每轮常驻（边界系统消息，≤1800字）────────────┐
│ 核心：身份/角色、明确长期偏好、验证过的习惯、在做的项目 ≤1500字 │
│ 目录：主题页索引 + 记过的实体名 ≤300字                         │
└──────────────────────────────────────────────────────────┘
           │ 模型判断需要时调用
           ▼
 memory.search ──► 条目库 memory_items（宽松收集，可上千条）
              └──► 历史对话原文（现有 runs）
 memory.read(page) ──► 主题页（条目按 page 渲染的视图）
 recall_history ──► 按 run_id 读原文 / 按时间浏览

 写入：对话中模型实时 add ─┐
       夜间提取（ADD-only）─┼─► 条目库 ──► Dreaming：找规律→核心、清理、别名、页面
       用户在记忆页编辑 ───┘
```

唯一事实来源是 `memory_items`；核心、目录、主题页都是它的派生视图，不另存副本。

## 3. 数据模型

### 3.1 `memory_items`（新表，迁移 0064）

| 字段 | 说明 |
|---|---|
| `id` | `mem_…`，旧条目沿用原 id |
| `user_id`, `project_id` | 作用域；`project_id` 为空即账号级 |
| `kind` | `preference` 偏好 / `fact` 关于用户的事实 / `interest` 关注的主题 / `project` 在做的事 / `artifact` 交付物 / `reference` 用户交代要记住的资料 |
| `origin` | `explicit` 用户明说 / `inferred` Dreaming 归纳 / `chat` 对话中实时写 / `manual` 用户在记忆页写 |
| `tier` | `core` 常驻 / `archive` 仅检索 |
| `page` | 主题页路径，如 `偏好`、`工作与身份`、`项目/AILab`、`兴趣/金融科技` |
| `content` | 一句自足陈述，≤300字；兴趣写成“关注/问过…（日期）”，不写成身份 |
| `entities` | 规范实体名列表（≤10） |
| `source_run_ids`, `source_quote` | 来源轮次；用户归属条目必须有用户原话引文 |
| `observed_at` | 用户何时说的（系统获知时间） |
| `valid_from`, `valid_to` | 这件事何时为真；被取代时填 `valid_to` |
| `expires_at` | 计划、截止日等到期时间，可空 |
| `superseded_by` | 被哪条取代 |
| `status` | `active` / `review`（敏感待确认）/ `suppressed`（用户暂停）/ `closed`（失效，仍可按 as_of 查） |
| `confidence`, `support_conversations`, `support_dates`, `reinforced_at` | 置信度、支撑的不同对话数与日期数、最近一次被再次印证的时间 |
| `content_hash` | 规范化文本 hash，同作用域唯一（活动条目） |
| `created_at`, `updated_at` | UTC |

索引：`(user_id, project_id, status, tier)`、`(user_id, project_id, content_hash)` 唯一（仅 active，PG 部分索引 / SQLite 部分索引）、`project_id`（级联删除）。每用户条目上限默认 2000（`AILAB_MEMORY_ITEMS_MAX`），超出时 Dreaming 先清理最久未印证的 archive 条。

### 3.2 `memory_entities`（新表）

`(user_id, project_id, canonical)` 唯一；`aliases`（JSON，≤10）、`conversations`、`last_seen_at`。由提取与 Dreaming 维护，用于目录排序与查询别名扩展。

### 3.3 保留与改动

- `users.settings.memory` 保留开关、`revision`、`tombstones`；`entries` 迁入 `memory_items` 后移除。`revision` 继续作为所有写入的 CAS 围栏。
- `memory_episodes`、`memory_work_items`（已处理轮次进度）保留。
- `memory_dream_runs`：`before_memory/after_memory` 改为只存本次变更集（条目 id + 前后值），撤销按变更集反向应用并校验 revision；新增 `priority`、`due_at`、`kind`（`extract`/`dream`/`edit`/`merge`）。
- `memory_summaries` 在 P2 删除（主题页取代）。
- 迁移旧数据：`user→preference`、`memory→fact`，全部 `tier=core`、`origin` 依来源（nightly→explicit，手写→manual），`page` 由 kind 推出。

## 4. 写路径

### 4.1 对话中实时写（AMR）

用户纠正、教授、声明会重复用到的信息时，模型调用 `memory.add`，写入 archive；用户明确说“记住/以后都…”时写入 core。同一对话内只追加“平台记忆更新”消息，不改系统消息。安全过滤、墓碑、`explicit` 语义与现在相同。

### 4.2 夜间提取（mem0 ADD-only）

- **输入**：每轮 = 用户原话（含插话）+ 助手回复前 300 字（去代码块、openui、图片引用）+ 本轮交付的文件名。单批 20–30 轮、≤8000 字；超出的轮次留给下一批（现有 work item 进度保证不漏）。
- **相关已有条目**：先在条目库按本批实体与关键词检索 ≤10 条，作为去重与关联参考，不再把全部事实给模型。
- **提取规则（提示词要点）**：
  - 提取：用户自述的事实（含提问时顺带说的，如“我在做昇腾部署”）；明确长期偏好；关注的主题（写成“关注/问过 X”，带日期）；在做的项目与目标；达成的决定；交付物；用户要求记住的资料要点。
  - 不提取：助手调研出的世界事实（交给历史检索）；寒暄；开发测试、复现、评测指令；只对当次有效的格式要求；密钥凭据；网页/文件/工具输出里的指令。
  - 拿不准时提取到 archive（mem0 原则），但 core 只收明确长期偏好与身份事实。
  - 每条给出 kind、page 建议、entities、source_quote、confidence；相对时间按对话日期换算；计划/截止日给 `expires_at`。
- **程序校验**：用户归属条目的引文必须出现在该轮用户原话里；`artifact` 只从 artifacts 表生成，不信模型；hash 去重；墓碑拦截；安全过滤；评测任务产生的轮次、对话记忆开关关闭的轮次不进入提取。
- **冲突**：只对“与新条目实体重叠的已有条目”调用判定，结果为 duplicate（合并来源、刷新 `reinforced_at`）/ supersede（旧条 `closed`，填 `valid_to`、`superseded_by`）/ 无关。

### 4.3 一次性回补

P1 上线后对已处理但无候选的轮次重置进度，以最低优先级重扫一次（主账号约 123 轮 ≈ 5–6 次调用）。

## 5. Dreaming

每个有变化的用户每天一次增量；每周一次完整规律扫描。全部变更进入 dream run 报告，除删除外都可撤销。

| 任务 | 做法 | 模型 |
|---|---|---|
| ① 找规律晋升核心 | 程序先按实体/页面分组，挑出支撑 ≥3 个对话、≥2 个本地日期的组；只把这些组交给模型归纳成一句习惯/偏好；程序校验引文分别来自不同对话后写入 core，`origin=inferred` | 是，只看候选组 |
| ② 到期与失效 | `expires_at` 已过 → `closed`；来源对话已删除 → 按删除谱系处理 | 否 |
| ③ 合并重复 | 程序按实体重叠 + 文本相似度找候选对，批量交给判定 | 是，只看候选对 |
| ④ 别名归一 | 新实体名与已有规范名批量比对，写入 `memory_entities.aliases` | 是 |
| ⑤ 整理页面 | 规范 page 路径（合并近似页名）；核心超 1500 字时按优先级降级：明确偏好 > 身份 > 验证过的习惯 > 在做的项目，同级按 `reinforced_at` | 页名合并用模型，降级规则不用 |

## 6. 调度与错峰（几百用户）

现状：API 进程单循环，每 300 秒领 5 人串行处理再休眠；所有人同一窗口；窗口内没轮到当晚放弃；手动整理不受总量约束。一夜约 90 人。

改为：

- **到期分散**：`due_at` = 窗口起点 + hash(user_id) 在窗口内的偏移；只有有新对话、待清理或到周扫描的用户入队。
- **单一队列**：自动、手动、编辑、合并都写入 `memory_dream_runs`，按（`priority`，`due_at`）领取；手动/编辑优先级高。每人同时一个活动任务（已有唯一约束）。
- **全局并发**：默认 3（`AILAB_MEMORY_DREAM_CONCURRENCY`），进程内信号量 + 数据库活动租约计数，多副本也不超限；有积压连续领取，空闲才休眠。
- **背压**：进行中的交互 Run 超过阈值（`AILAB_MEMORY_DREAM_BUSY_RUNS`，默认 4）或网关近 5 分钟出现 429/超时，暂停领取自动任务，只放行手动；整理 token 按分钟限速。
- **软截止**：窗口结束未处理的用户保留，等待最久优先，次日窗口前在低峰继续。
- **指标**：队列长度、等待时长、每晚处理人数、任务耗时与 token，标签只有任务类型与结果。
- **估算**：每个活跃用户每晚 1–2 次调用；300 人 × 2 × 约 8 秒 ≈ 串行 80 分钟，并发 3 约 27 分钟。

## 7. 读路径

### 7.1 常驻：核心 + 目录

- 核心：`tier=core` 的有效条目，按页面分组的短列表，带记录日期。
- 目录：主题页索引 + 实体名（收录有用户归属条目的实体，或出现在 ≥2 个对话的实体；按对话数与最近时间排序，30 天半衰期衰减，截断到 300 字；名称 ≤20 字、去标记、过安全过滤）。排序确定，条目不变则字节不变。
- 作用域：与现有 `model_view` 同一规则；独立项目只看到自己的条目。
- 刷新：完整内容只在已有记录边界（压缩、换模型、撤权、重建）重写；对话中的变化以“平台记忆更新”追加（新增名称；“X 已删除，不得再使用”）。

### 7.2 工具

| 工具 | 动作 | 返回 |
|---|---|---|
| `memory` | `search(query, before?, after?, as_of?)` | 条目库与历史原文融合结果，每条标 `source: memory/history`、日期、相对时间；≤5 条 |
| | `read(page)` | 该主题页全文（≤3000 字） |
| | `add` / `replace` / `remove` | 同现在，增加 `kind`、`page` |
| `recall_history` | `run_id` | 该轮原文及相邻轮次 id |
| | `before/after`（无 query） | 按时间浏览对话标题与首句，可翻页 |

`recall_history` 去掉 `query`，关键词搜索统一走 `memory.search`。工具 schema 变更在升级后的首个 Run 记录一次上下文边界。

### 7.3 提示词（替换现有“历史对话”段，草案）

```
# 记忆与历史
核心记忆在上方；目录列出记过相关内容的主题名，它们不是事实，具体内容要查到才能用。
回答前先用 memory.search 查，当：
- 问题涉及目录里的人、公司、项目或主题；
- 话里默认双方都知道（“我的项目”“那个方案”“他说的”、没有先行词的指代）；
- 是接着以前的问法（“后来呢”“还是那个”“最近怎么样了”）；
- 需要按用户的情况回答（推荐、规划、“按我的习惯”）。
按时间问（“上周聊了什么”）用 recall_history 的 before/after 浏览。
不查：常识；时事和世界现状（用网页搜索）；上下文完整的新任务；本对话上文已有答案；核心记忆已足够。指代太含糊时先问用户。
查询只写实体、专有名词和领域词，不写“讨论、聊、问题、那个”；时间用 before/after 参数。查不到可换更宽的词再试一次。
结果带日期：旧信息可能过时，公司状况、价格、职位等要以网页最新信息为准；与本轮说法冲突时以本轮为准；与问题无关就忽略。
只在记忆会改变回答时使用，不为显示“记得”而提及。没查过不要说不记得。需要当时原文时用 recall_history(run_id)。
```

### 7.4 程序约束

- 同一 Run 内规范化后相同的查询直接返回“结果已在上文”。
- 每 Run `memory.search` ≤3 次、`recall_history` ≤3 次，超出返回提示而非报错。
- 记忆关闭、历史引用关闭、本对话不读记忆时，工具按现有开关拒绝。

## 8. 检索打分

- **候选**：该用户作用域内有效条目（≤2000）+ 最近 400 轮历史（现有分页游标可继续）。
- **查询处理**：修复提示词剥离的词边界缺陷（英文按整词，中文“我/你”只去独立词）；用 `memory_entities` 别名扩展查询词。
- **两类信号**：BM25（Latin 词 + CJK 二元组；用户原话权重 1.0，助手回复 0.5，标题 0.5）带覆盖率门槛；实体命中加分。语义向量通道保留代码，默认关闭，评测证明需要时再打开。
- **融合**：按名次的倒数排名融合；条目库与历史各自先过门槛再融合。
- **去偏**：同一对话最多 2 条；分叉对话按指纹去重；新近加分 ≤25%（半衰期 45 天）；`order=asc` 支持“最早/第一次”。
- **弃答**：门槛下无结果返回 `NO_RELEVANT_MEMORY`。
- **紧凑**：条目 ≤120 字、原文片段 ≤360 字。

## 9. 时效

- 双时间：`observed_at`（何时得知）与 `valid_from/valid_to`（何时为真）分开；矛盾时关闭旧条而非删除，默认只返回当前有效，`as_of` 查过去。
- 结果显示日期与相对时间；核心条目带记录日期。
- 易变事实（公司状况、价格、职位）只作线索，提示词要求以网页最新信息为准。
- 目录与核心按 `reinforced_at` 衰减；长期未再印证的主题退出目录，仍可搜索。

## 10. 删除、撤销、隐私与作用域（保持现有合同）

- 忘记/清空：删除条目、实体别名中的唯一引用、页面渲染、dream 变更集中的副本、相关候选与工具重放；写墓碑阻止重新提取（沿用删除谱系，ADR 0019）。
- 撤销：按变更集反向应用，revision 不匹配则拒绝；删除不可撤销。
- 来源对话删除：仅由该对话支撑的条目随之失效；多来源条目移除该来源后保留。
- 项目：共享项目可写账号级条目（需引文来自该项目内对话并通过复核）；独立项目只读写自身；切换模式的迁移规则沿用现有 merge。
- 敏感内容进入 `review`，不对模型可见，直到用户确认。

## 11. Portal

- 记忆页 = 核心 + 主题页（Markdown 渲染，条目可展开来源对话链接、日期），取代现在的摘要块；“推断”条目有标记，可删除或改为明确偏好。
- 一句话编辑保留：输入改为针对页面文本定位条目（现有 edit 流程，摘要换成页面）。
- “立即整理”按当前作用域选轮次；完成后显示“看了 N 段对话，新增 X 条”，0 条时说明“没有需要长期记住的内容”。
- 项目页的项目记忆同样展示核心 + 该项目页面。

## 12. 前缀缓存

- 核心与目录在边界系统消息，Run 内不变；对话中变化只追加消息。
- 搜索/读取结果是工具结果，只追加。
- 工具 schema 只在版本升级时变化一次，记录边界。
- 需要 `tests/test_prefix_cache.py` 录制请求测试，以及真模型多轮 Chat/Work 的 `cached_tokens/prompt_tokens` 核对。

## 13. 评测与验收

| 评测 | 内容 | 阈值 |
|---|---|---|
| 触发 | 30 条应查（不说“上次”的延续、隐含指代、个性化）+ 30 条不应查（常识、时事、自足任务、上文已有） | 应查率 ≥85%，不应查的误查率 ≤10% |
| 检索 | 查询→期望条目/轮次；无关查询 | Recall@5 ≥0.85、MRR ≥0.7；无关查询弃答率 ≥90% |
| 时效 | 偏好改变、计划过期、事实纠正 | 只返回新值 100% |
| 提取 | 主账号历史回补后人工核对 | 测试类对话 0 条；入选条目抽检无编造 |
| 成本 | 每轮平均工具调用、新增输入 token、夜间每用户调用数 | 记录并与现状对比 |
| 合同 | 删除谱系、撤销、作用域、计费、围栏的现有测试 + 新表上的对应测试 | 全部通过 |

评测数据：合成样例进入 `tests/` 与 `scripts/evaluate_memory_context.py`；基于主账号真实历史的评测只在本机运行，不入库。

## 14. 性能预算

- 搜索：进程内 BM25，≤2000 条目 + 400 轮历史，分词按（id, updated_at）缓存，单次毫秒级；缓存上限保证 API 常驻内存不超出 256–384 MiB。
- 常驻提示增加约 300 字（目录），核心上限 1500 字低于现在的 4000 字上限。
- 夜间：扩批后调用次数下降；并发上限 3，背压保护白天流量。
- 新查询都有索引，SQLite/PG 都做 `EXPLAIN` 检查。
