# 记忆摘要与项目记忆模式（2026-11-01）

分支 `feat/memory-summary`，base `origin/main@4c6f092`。用户授权：设计并实施、PR、merge、部署；后端实现/测试/部署由 Codex（gpt-6.1-sol medium）完成，Claude 负责设计、Portal 与最终质量。

## 1. 目标与判断

用户看到的是“AI 记得我什么”，不是事实库的逐条记录和每晚的整理日志。逐条事实（`users.settings.memory.entries`）仍是模型读取、删除谱系、撤销与召回的唯一来源；摘要是从这些事实派生的只读文本，只给人看，不进入模型上下文（不影响前缀缓存与召回精度）。

| 问题 | 决定 | 理由 |
|---|---|---|
| 页面展示什么 | 只展示一份“你的记忆”摘要（账号一份、每个项目一份），点进去看全文 | 逐条列表和每日整理报告是排障材料，不是用户价值；摘要由事实派生，不会与事实分叉 |
| 个人偏好 / 长期记忆 | 界面不再区分；后端 `kind` 保留（`user` 类总进入上下文） | 摘要按主题组织，分两栏只增加认知负担 |
| 用户如何修改 | 在摘要里用自然语言说“记住/改成/忘记…”；后台把指令转成对事实的增删改，再重写摘要；可撤销最近一次 | 改摘要文本无法回写事实；改事实才能让模型行为真正变化 |
| 整理日志 | 不向用户展示；`memory_dream_runs` 与 `/v1/memory/dreams*` 保留给排障与撤销 | 用户要求 |
| 项目记忆开关 | 从账号级 `project_only` 改为每个项目的 `memory_mode`，在项目里设置 | 是否隔离是项目属性，不是账号属性 |

## 2. 项目记忆模式

`projects.memory_mode ∈ {shared, isolated}`，默认 `shared`。

| | 共享（shared） | 仅本项目（isolated） |
|---|---|---|
| 项目内对话读取 | 账号事实 + 本项目事实 | 只读本项目事实 |
| 项目内对话学到的事实 | 关于用户本人的通用事实进账号；只对本项目有意义的留在项目 | 全部留在项目 |
| 引用历史对话 | 项目外对话与所有共享项目的对话互相可引用 | 只引用本项目对话；项目外看不到它 |

### 迁移（两个方向都允许）

- **共享 → 仅本项目**（确定性、同一事务、无模型调用）：证据全部来自本项目对话的账号事实改为本项目作用域；证据混合或无证据（手写）的账号事实保持账号级。之后本项目不再读取账号事实。
- **仅本项目 → 共享**（融合，不是追加）：项目事实先原样保留在项目内（项目里照常可用，不丢不漏），项目标记 `memory_merge_requested_at` 并立即排一次整理。整理把每条项目事实与账号事实对照：
  - 与账号事实重复 → 并入账号事实（合并证据），删除项目副本；
  - 与账号事实冲突 → 按有效时间保留较新的，较旧的失效（沿用现有失效语义，可撤销）；
  - 关于用户本人的通用事实 → 改为账号作用域，保留 id、证据与有效时间；
  - 只对本项目有意义 → 留在项目。

  不直接把项目事实批量改成账号级：那会制造重复和互相矛盾的事实，也会让摘要失真。融合失败（模型不可用等）不改数据，标记保留，下一次整理重试；融合完成前又切回“仅本项目”则清除标记。
- 旧数据：`project_only=true` 的用户，其所有项目迁为 `isolated`；之后账号文档不再有 `project_only`。降级时只要用户有任一隔离项目即恢复 `project_only=true`。

## 3. 摘要

- 存储：`memory_summaries(user_id, project_id NULL=账号, text, source_digest, generated_at)`，账号与每个项目各一行；项目删除级联删除。
- `source_digest` = 该作用域模型可见事实（active、未暂停、未失效）的 id+内容摘要。摘要与事实一致与否由 digest 判断，不靠时间戳。
- 生成时机：每次整理（夜间或“立即整理”）结束、每次对话式修改后，只重写 digest 已变化的作用域；每次整理最多重写 5 个作用域，请求的作用域优先，其次账号，余下下次。无摘要且无事实不算过期；已有摘要的作用域清空时直接写空文本，不调用模型。批次事实、游标与最终状态先同事务持久化，租约保留至摘要结束并在调用前续租（崩溃后过期），摘要派生刷新（包括失败批次）不影响批次完成或重投判断；摘要调用仍逐次计费。
- 内容：模型只依据该作用域事实生成，不得新增推断；用户语言、第二人称、按主题分小节的短 Markdown，≤800 字；不含证据、日期流水和内部 id。
- 首次打开没有摘要但已有事实时，Portal 自动发起一次整理（之后靠 digest 不再重复）。

## 4. 对话式修改

`POST /v1/memory/summary/edit {project_id|null, instruction}` 创建 `trigger=edit` 的整理记录（复用单用户单活动整理约束、快照、计费与撤销）。后台一次模型调用把指令转成对该作用域事实的 add/replace/remove，按“用户本人明确要求”写入（`source=user, explicit`，仍拒绝密钥/口令），再重写该作用域摘要，`report.reply` 给一句结果说明（没有可改内容时说明原因、不改数据）。事务与用户锁不跨模型等待；提交前复核该作用域事实，冲突则失败让用户重试；设置或其他作用域的变化不构成冲突，提交以当前完整文档保留它们。撤销最近一次修改同时恢复修改前的摘要。

## 5. 其他决定

- 推断出的敏感个人信息（`review_required`）不再以“待确认”状态静默入库；没有逐条列表后用户无法确认它们。用户明确要求记住的照常保存。既有待确认/暂停条目不动，仍不进模型、不进摘要，“清空”时一并删除。
- “清空”只删当前作用域的事实与摘要，走现有墓碑与原话副本清除。
- “立即整理”在没有新对话、没有待融合项目、摘要也都最新时返回 `nothing`；关闭自动记忆时仍可整理摘要与融合，只跳过从对话抽取。

## 6. 成本

- 摘要：每个变化的作用域一次短调用（输入 ≤12k 字事实，输出 ≤800 字），只在事实变化后发生；每次整理至多 5 次。
- 融合：每个切回共享的项目一次调用（≤100 条事实）。
- 对话式修改：每条指令一次编辑调用 + 一次摘要调用。
- 均走现有 reserve/settle 计费；无新常驻任务、无新依赖。新查询（摘要按用户/项目、历史召回按项目模式）有索引并做双库 EXPLAIN。

## 7. 界面

- 记忆页：一个列表——使用记忆、自动记忆、引用历史对话、夜间整理四个开关，加“你的记忆”入口行（显示摘要前几行，点开为全文、立即整理、对话式修改、撤销、清空）。去掉整理日志、搜索/范围筛选、逐条编辑与字数配额。
- 项目页：项目菜单新增“记忆”，弹窗内选择共享/仅本项目（切换前确认迁移效果），下方为本项目摘要，交互同上。
- 技能页：行尾操作统一为“开关在前、⋯ 固定在最右”，没有开关时不留空位；扫描中显示为进行中而非“无法使用”。
