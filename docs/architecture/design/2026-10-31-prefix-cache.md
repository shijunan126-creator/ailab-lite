# 模型请求前缀缓存

基线 `f316b85`，C2c 代码基线 `de74d01`。同一会话段中，主循环每次请求使用相同工具目录，并以原消息、上次助手输出及新消息顺序追加。前缀结构是供应商缓存命中的必要条件，不能证明实际命中率。

第一个 system 消息是按模式、模型能力版本化的平台规则；第二个是会话上下文，包括记忆快照。用户输入、工具调用和结果随后依次追加。运行开始按预算选定完整或 v1 精简工具目录，固定 reasoning 回传策略，工具结果插入时完成裁剪。图片 checkpoint 保存授权引用与内容哈希；旧 checkpoint 第一次授权读取建立哈希。会话子 run 恢复父 checkpoint，fork 建立新前缀。

记忆变化按 revision 追加通知，删除前核对完整可见列表，删除通知只含 ID。摘要或重建边界可替换记忆快照。旧记忆布局在首次使用时声明 `rebuilt` 并建立新布局，checkpoint 的待处理工具和已确认交付仍保留。

边界以 `agent.context_boundary` 记录：模型切换为 `model_changed`，授权失效为 `access_revoked`，压缩为 `compacted`，旧布局或快照不存在时为 `rebuilt`。继承父快照时 recall 来源失效则丢弃该快照，从仍有效的历史重组；重组只读取上下文，不重跑工具。每个 run 在继承上下文及首次使用新 recall 结果时逐来源验证，并将已验证的 run_id 保存在 checkpoint；同一 run 后续步骤不重复调用。运行中撤权在下一 run 启动时检测，失效的继承快照触发重组；恢复同一 run 沿用已验证状态。模型 fallback 保留消息并记录切换边界。

轮内、跨轮和无快照历史摘要均使用同模型、同工具，以摘要指令追加在已有消息之后，并设置 `tool_choice=none`。压缩调用对临时错误重试但不切换模型。轮内新基底保留本轮用户原消息（包括附件），并以平台提示保留已确认交付的前 64 个实际交付文件名和沙箱路径及总数（旧记录缺文件名时使用路径末段）；跨轮压缩也带上父轮交付记录和当前用户消息。近期保留完整的 assistant/tool 组，组内 recall 结果在压缩边界替换为重新查询提示。摘要提示要求不保留 recall 原文或仅源自 recall 的事实，最多保留查询主题。真实模型是否遵守该要求尚未验证，提示词本身不是确定性隔离。

当前会话最新 checkpoint 保留，子快照成功后父快照七天到期；单个 checkpoint 未压缩默认上限 4 MiB，配置上限 16 MiB。磁盘消耗取决于对话、分支和压缩率。新消息、助手输出、摘要边界和模型或工具版本变化仍会造成未命中；供应商的最短前缀、路由和 TTL 也影响命中。标题、记忆整理和技能草稿是独立调用；指标按模式和调用类型累计 prompt/cached tokens，不使用用户或会话 ID 标签。真实模型命中率、成本和摘要质量未测。
