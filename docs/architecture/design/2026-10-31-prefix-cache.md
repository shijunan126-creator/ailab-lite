# 模型请求前缀缓存（C2，未完成）

基线 `f316b85`，工作分支 `fix/prefix-cache-render`。目标是同一会话段内每次主循环请求保持相同工具，并以原消息、上次助手输出及新消息顺序追加；前缀结构只是供应商缓存命中的必要条件，不能证明命中率。

请求的第一个 system 消息是按模式、模型能力版本化的平台规则，第二个是会话上下文；用户输入、工具调用与结果随后依次追加。运行开始选定完整或 v1 精简工具目录，固定 reasoning 回传策略，工具输出在插入时裁剪；图片 checkpoint 使用授权读取及内容哈希。会话子 run 通过父 checkpoint 恢复消息和工具；fork 建立新前缀。记忆变化通过 revision 对比后追加通知；先对照完整可见列表以免把相关性筛选遗漏当作删除，删除通知只含 ID，已发出的记忆工具结果不重写。

允许 `model_changed`、`access_revoked`、`compacted`、`rebuilt` 边界，并以 `agent.context_boundary` 记录。跨轮和轮内摘要请求使用原消息末尾追加指令、同模型同工具、`tool_choice=none`；压缩后保留两个 system 消息、摘要及可保留的完整近期组。含 recall 的压缩提示要求只保留查询主题，并且不保留原始近期组；真实模型遵守该要求尚未验证，提示词本身并非确定性隔离。

**尚未完成：** recall 工具结果每次调用前仍需重新查询以验证来源，但保留原结果；来源失效时安全暂停，撤权后自动重建且保留已确认副作用的路径未完成。无快照的历史重组仍使用旧分块、低价模型摘要路径；旧快照缺少记忆观察状态的迁移、记忆可见范围变化而 revision 不变的撤权检测、压缩时记忆快照替换、运行中模型 fallback 的边界事件、剩余 harness 场景及完整验收仍待完成。上述缺口使整体追加式契约尚未成立，不应视作可集成结果。

保留成本：当前会话最新 checkpoint 保留，子快照成功后父快照七天到期；单个 checkpoint 未压缩默认上限 4 MiB，配置上限 16 MiB。具体磁盘消耗随对话、分支及压缩率变化；供应商实际缓存命中率、价格、摘要质量均未测。

即使结构满足，仍会有新消息、上次输出、摘要边界、模型或工具版本变化产生的缓存未命中；供应商的最短前缀、路由及 TTL 也可能使重复前缀未命中。标题、记忆整理和技能草稿是独立调用，不计为主循环的延续；指标按模式和调用类型累计 prompt/cached tokens，不使用用户或会话 ID 标签。
