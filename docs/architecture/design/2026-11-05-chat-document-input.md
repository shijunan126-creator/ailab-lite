# 文件输入：安全入库、Work按需操作、Chat按需准备

状态：研究修订后的实施建议，未开始产品实现。2026-11-05用户要求给出具体方案，并要求读文字、搜文档采用独立工具名；不再沿用此前“一个read工具兼做搜索”的设计。

核对基线：`fix/ocr-lifecycle-pr@87315188`，PR160合并产品树为`main@fdc0a05`；不代表当前部署版本。关联：[原视觉/等待ADR](../adr/0026-document-visual-coverage-and-file-waits.md)、[Chat/Work历史设计](file-context-ocr/02-chat-work.md)、[前缀缓存ADR](../adr/0030-prefix-stable-model-requests.md)、[压缩ADR](../adr/0033-context-epoch-band-process-snapshot.md)、[已知视觉覆盖缺口](../../reviews/2026-11-04-chat-visual-coverage-followup.md)。本稿替换此前候选规则；最新[读取流程研究](../../reviews/2026-11-05-document-reading-workflow-research.md)补充上游证据、混排与模式隔离，不把设计稿视作实施授权。

## 1. 目标和职责

普通上传只安全入库；Work根据任务操作原文件；Chat引用时才准备必要内容；视觉读取不先OCR；处理有限额；派生结果复用且可回收。

所有读取、预览、截图、OCR、转换、缓存和清理改动均以服务端与用户设备的性能和资源生命周期作为交付门槛，禁止只验证功能通了。平台执行权限、内容准备、OCR/渲染路由、输入分档、并发/容量/截止时间。不给模型新增后台策略系统提示词。工具说明讲输入、输出、定位与不可用行为；按需加载的模式阅读说明固化“先导航、按目标选文字/图像/OCR、核对范围”的操作方法；不加入TTL、队列、引擎等后台配置。Office操作由实际加载的skill指导；保留通用的“未读/未搜不能声称覆盖”准确性要求。

目标是不新增常驻服务或为了上传额外调用模型；按需工具读取可能增加模型往返，总延迟和费用须实测。

## 2. 上传、Work、预览与Chat

### 2.1 普通上传

校验归属/权限、原始大小、实际类型、完整性摘要、安全扫描和有界压缩包安全检查。失败/无法确认安全不放行。不自动提取全文、建立正文索引、转换PDF、生成页面图、OCR、Office预热或语义摘要。

安全通过即可供Work取原文件。安全就绪与派生就绪分开，不能以空正文冒充准备成功。文件不固化Chat/Work属性，同一不可变文件版本可跨模式消费。

此规则针对普通输入附件。模板/品牌/技能专用导入与输出成品交付按各自既有必要合同保留，逐入口验证。

### 2.2 Work

首条模型消息只有文件身份、版本、类型、大小及原文件工作区位置。模型按任务加载Office技能，用Work沙箱读取、计算、编辑及验收，不等待平台整份解析。平台已有兼容派生可以复用；无派生时可直接操作原文件。Work图片附件仍按所选模型的图像输入能力准备必要表示，不把“原文件引用”当成模型已经看到图片。

Chat的read_document/search_document/view_document从新Work工具目录、发现与执行入口排除，主任务/并行子任务一致。Work保留找资料库文件、复制原文件、交付与工作区查看能力；所有Office读取/编辑/渲染在当前Work沙箱进行，子任务共享该沙箱但用独立工作目录。不能因查看输入附件再租平台render沙箱。

Work需要OCR时，由当前lease绑定的受限工作区图片/区域适配调用已有OCR执行器；不向沙箱暴露密钥、不装第二份权重、不借Chat文档工具绕回系统渲染。该适配尚未实现，不能声称现在已支持任意工作区文件OCR。

### 2.3 主动预览

用户打开预览才生成所需表示，命中缓存复用；取消上传回调中的普通附件eager preview/reader/prewarm。交付成品现有预览合同不在本次取消范围。

### 2.4 Chat

引用并发送或显式准备时触发：先按已知大小/安全/结构限额准入，再准备原生文字/小型结构索引；仅图片/扫描页或确需视觉内容时转换/渲染；相同源版本和派生器版本复用缓存与在途job。浏览资料库不启动准备。

文件安全状态沿用现有生命周期；派生状态独立记录为absent/pending/ready/failed，分别对应native_text、page_images、ocr_text，并绑定源版本/派生版本及job。Chat按所选模型需要的表示检查可用性，不统一等所有派生ready。准备失败保留安全原文件，Work仍可用；不能发送假空白内容。

准备使用持久job/outbox、幂等和CAS发布，复用文件等待恢复、取消与截止时间；用户界面只保留必要的准备中/失败/取消行为，不增加已读页数UI。

### 2.5 用户浏览器承担展示与按需截图（减负建议，未实现新的路由）

优先复用Portal现有四格式原生viewer、capture_view及client-call回传能力，不新增浏览器办公服务、OCR权重或通用执行协议。

- 人看的原文件展示、缩放、分页、选区与PDF页图在浏览器完成；图片展示直接用原图，允许本地生成展示缩略图/有界压缩副本但保留原文件字节。Word/PPT/Excel浏览器布局可能与Office不同，模型所见须标记表示来源，不能声称精确导出或重算。
- 模型请求查看已有在线viewer中的合法页/region时优先复用当前viewer截图，只回传所需图，平台复核当前文件/版本/范围与结果尺寸后追加模型输入。当前截图桥接已存在，但view_document接入该路由仍是新增工作，不能宣称现已端到端接好。
- 当前OfficeView先等待服务端DocumentIndex/viewer.json，原生显示不是零后台处理。第一阶段拆出打开所需的有界元数据/授权文件入口与完整文字索引，保持真实选区/精确引用的既有校验合同，不用上传客户端自报的“已扫描安全/已搜索全文”替代服务端事实。缓存与model_read覆盖分别记录。
- viewer不可用/关闭、客户端调用超时或表示不支持时，对同一请求只启动一次服务端后备；按第8.1节的原子执行权与接管规则，避免无界重复计算并保证只有一个有效结果。原文件安全/权限/版本失败不触发转换后备。大文件/手机资源不足时允许明确后备或资源错误，不能把本地渲染当无限算力。
- 先取消普通上传的eager preview，再按消费请求选择browser/server，避免前端展示同时后台仍在整份导出。服务端保留页面处理能力供离线/刷新/后台任务以及确需Office排版/转换的操作；Work的后备渲染仍在自己的工作沙箱，不能因此另租系统render沙箱。
- 第一阶段不迁OCR、完整文档索引/跨轮检索、复杂重算、PDF精确导出。已打开页面的选中文字可复用，完整正文搜索暂用服务端已有实现。下一阶段只有测量表明索引仍是主要成本时，才考虑复用浏览器已有文本层/结构（受版本/来源/限额约束），不另建一套平行解析栈。
- 客户端计算结果是用户提交数据，不是安全或权限证据；只能回传调用绑定的文字/图片，不能把服务密钥、存储路径和任意网络访问权交给浏览器。已显示不等于模型已看，必须有成功回传/模型消息覆盖证据。

这样可以降低常见在线预览与模型看当前页的转换/栅格化负载；仍有文件传输、授权与少量结果存储成本。不能承诺移除整个系统沙箱池。验收需检查服务端无重复job、viewer首开不等完整解析、截图在线/关闭/超时/多tab抢占/版本变化、浏览器RSS/主线程响应、服务端CPU/RSS和图像回传字节。仅当以上链路通过，才能宣称服务端减负。

## 3. 三个独立工具

仅对新Chat run使用统一命名：`read_document`、`search_document`、`view_document`。名称统一表示对一份已授权文档执行的操作；避免read_pages不能表达Word段落、Excel区域的问题。

| 工具 | 参数轮廓 | 返回/行为 |
|---|---|---|
| `read_document` | file_id、selector可选、text_source=native/ocr、cursor可选 | 默认读原生文字/结构内容，不隐式OCR；模型明确选择ocr时读缓存或准备所选页/区域OCR；单次正文最多8000字符，按完整结构边界分页，超长单块用游标继续 |
| `search_document` | file_id、query、selector可选、cursor可选 | 确定性关键词检索，默认20条命中、片段最多200字符/条、正文总返回最多8000字符；返回页号或结构定位及可续读游标 |
| `view_document` | file_id、target（pages/region/image资源）、cursor可选 | 返回所选物理页整页图、裁剪或已支持安全提取的位图（一次最多4张），缺缓存才渲染，不启动OCR；图像还须服从模型真实能力和剩余输入预算 |

selector使用类型化的pages、Word heading/anchor或Excel sheet/range，互斥而非混用；有界schema，实施时镜像API契约。源版本绑定于平台授权文件与返回cursor，不接受模型构造存储路径。所有结果带file/version、表示版本、实际覆盖/缺失、truncated及下一游标。不存在/无权限统一404，损坏/资源超限/不支持/处理中分别有稳定原因，不能返回假成功空文本。

读取和搜索分工：read不接query；search只给定位/片段，需要上下文再read。`search_library`仍找文件名，不搜文档正文。

### 3.1 明确选择文字表示，不让OCR变成隐式副作用

新Chat保留三个工具；read_document增加text_source=native/ocr，不新增第四个OCR工具。用户提取文字入口/底层OCR业务API继续复用。

- 默认native返回原生文字及已知覆盖，缺文字返回missing与可选操作，不自动OCR。模型需要OCR时显式指定范围与text_source=ocr，命中兼容缓存复用，否则触发有界job。
- 即使页面有原生文字，也允许对所选页/region OCR；页眉/隐藏层不代表图片中文字已经覆盖。OCR结果另存来源与区域，不覆盖原生文字；质量可疑不能只靠字符数判定。
- view_document仅看图不OCR。search_document仅搜现有文字，报告native/OCR覆盖与unknown范围；模型可先read(ocr)准备选定范围，再search，不隐式整篇识别。
- 同run新OCR最多4批、合计80唯一页，单批≤20；仍受时间、内存、配额与容量限制。该工作量预算不是文件总页数准入。
- 非视觉模型可以读取原生/OCR文字，但不假装理解图形；其不能看图的能力边界由平台强制。Work使用第2.2节工作区操作路径，不使用Chat这三个工具。

### 3.2 检索与位置合同

不引入向量服务或语义检索，第一版做有界关键词匹配：原生索引/可用OCR块按稳定顺序扫描，Unicode归一化后的字面匹配，返回准确源位置；缓存查找不等于全文已搜索。文件规模由第5节限制，单次最多检查100个块并返回search_cursor；即使本批0命中，只要有next_cursor仍未搜完。当前块内未返回的命中也必须编码到cursor，不能因20条limit漏掉后续命中。累计扫描直到游标结束才完成可用文字范围检索。游标绑定文件/派生版本/query/selector；文本版本变化返回cursor_stale，不拼接新旧结果。实现无需新FTS/embedding依赖，性能不达预算时停止并返回续读/超限，不退回无界全文件扫描。

PDF/PPT页号使用原生页号；Word文字按heading/anchor、Excel按sheet/range读取/搜索，不承诺无需转换就有物理页码。实际转换后可以读取该PDF表示的页文字并带原文件身份/渲染版本，但不声称其与原生段落/单元格一一对应。页码来自转换器输出，不能由模型猜算。

### 3.3 旧run兼容

不能直接改掉已存checkpoint的工具名/工具集合。发布时对新run启用新工具目录版本；旧run保留原有`read_library_file`/`view_attachment`/`extract_text`定义和路由到原语义的兼容处理，恢复不改工具列表。API底层可共享授权/缓存实现；相同run不能同时展示新旧同义工具。最终别名移除以旧run生命周期结束为条件，不趁压缩偷偷改名。

### 3.4 固化的阅读流程：导航→选范围/表示→读取→核对

Chat引用时先给一份有界内容地图：文件/版本、已知页/块数量、已有outline、稳定locator、原生文字/视觉/OCR各自可用性、已检查范围与下一导航cursor。无目录时用页号/段落/表格/sheet，不生成虚构语义目录；未知标unknown。小文件可直接带预算内正文/必要图，较大文件的图片按需取，不先生成全文件缩略图。

1. 看导航与当前问题，确定目标范围；有文字线索先search或read，用户明确页/区域可直接view。
2. 选择表示：读文字用native；理解图片/布局用view；需要扫描文字或可疑文字层复核时显式ocr。混排可组合操作，不以has_text互斥排除视觉/OCR。
3. 无文字/目录时按稳定locator分批view，必要时OCR；不存在图片语义检索时不声称能按关键词搜图。只有原生图片可安全直接提取时可看image资源，否则用页/region渲染。
4. 回答前核对工具返回coverage/missing/truncated/unknown；无匹配仅指实际搜索范围；读过文字不能声称看过图，OCR不能代替布局理解。

流程写在按模式加载的阅读入口/工具说明，文件事实由工具提供，不向system塞后台策略。Chat不携带制作/exec指引；Work仅携带office-read/工作区查看/OCR适配说明。生成源为vendor/office-suite/build.py，连同viewer/引用模块和子任务允许列表审查，生成SKILL不得手改；保持上游操作资源完整，按模式选择入口而非复制两套上游正文。

复用runtime的ParsedDocument/manifest合同，但现有runner首次会整份解析。真范围读取/轻量probe需扩适配器，不以模型侧分页伪装解析侧懒处理；已缓存索引直接用，首次超限/partial如实返回。PDF现有3000页索引边界是实现覆盖事实，不可冒充新产品页数准入限制。

## 4. Chat输入与视觉选择

### 4.1 小文档整份给

用户已接受的初值：本轮全部inline附件正文合计≤`min(24K token,20%模型输入预算)`、文档页图合计≤8，还须满足当前实际剩余上下文、模型图像数量/像素/字节限制。

平台装配原生正文及必要页图。视觉模型扫描页直接发图，不先OCR；纯文字且不需要布局时只发文字。非视觉模型的显式图片文字任务按有限OCR路径准备；不自动对全部附件OCR，不声称理解图形。图片输入的原有独立数量限制与文档页图限制分别校验。

附件策略冻结在本轮消息记录，重试/恢复沿用；历史消息只保留一份，不在后续轮重复附加。多附件按最大者优先转按需，稳定序号打破同大小平局，直到合计满足预算。

### 4.2 超过inline门槛但未超处理上限

首条只放身份、版本、已知页数/块数、目录和紧凑文字/视觉可用性标记；全部附件元数据/目录合计≤2000 token，不为每份附件各分配2000。未知物理页数如实标未知。模型按三个工具读取，工具目录不包含文档能力的模型不能进入此档，明确建议缩小文件或换模型。

不新增后台分档/限额/OCR系统提示词；模型看到平台准备的内容和工具的操作合同。工具与答案记录实际覆盖，全文类任务未读全不能冒充全文完成；不显示“已读x/y页”。

### 4.3 图多时如何取图

必要页图合计超过8张即不进入整份inline图像档，走on_demand；不能自动截前8张并把文件标为完整。8张是首次inline预算，4张是单次view预算，均不是文档或对话累计可看图片总数上限。模型实际图像/上下文预算可进一步降低单批数量。

第一条消息带有界目录和文字/视觉可用性索引，不先渲染全部页或为每张图调用描述模型；过长索引分页，read_document无selector时返回下一段有界导航/内容及cursor，不能把全部页标记塞进2000token。可用的周边原生文字/图题提供定位线索，但不冒充图片语义。

- 用户指定页：直接view_document读取这些页，最多4页/次。
- 用户问某主题：search_document搜已有正文/标题/图题，按返回位置定位候选页，再view_document看图；Word/Excel无法准确从结构映射物理页时，返回实际结构定位并进行受限页定位，不猜页号，无法定位则让用户指定页/范围。
- 纯图/扫描件没有文字线索：不能声称关键词能搜图片内容；按页码范围逐批看，或用户指定范围；确需扫描文字检索时由模型显式选text_source=ocr准备范围。第一版没有图片语义检索/全库图像embedding。
- 用户要求看全部图：分批view，每批≤4，按工具页号遍历并记录实际覆盖。受同轮时间、输入/输出、上下文、配额与资源预算约束；不足时明确已完成范围和剩余部分，不承诺无限读取，不静默丢图。后续追问可取新的范围，不能重置同run既有deadline。

平台只按请求页生成/复用页图。Office可能仍先整份导出PDF，不能把“按需渲染页图”说成“Office只转换了4页”。

### 4.4 表示优先于转换格式

原生读/搜不转PDF；原图或已验证的独立内嵌位图可直接看/OCR，不转PDF。图片资源枚举与关系定位是新增适配，当前runner并不提供完整图片目录；不可把媒体包路径/alt文本冒充已读图片。未支持时明确失败或改看页，不偷偷丢掉上下文。

PDF只渲染目标页/区域；Office需要整页排版、原生图表、连接线/组合对象或文字图片关系时，用已有LibreOffice→PDF→选页图片后端，复用转换结果。直接提图不能保留叠字/裁剪/组合布局，不替代整页视觉理解。Chat不开任意exec/插件安装，即便名为只读，仍可耗尽资源/泄漏文件；只开放有授权与限额的固定操作，后台可用同源runtime。

### 4.5 视觉页选择

PDF表格线/边框、PPT普通文本框不直接判为必须发图；图片、图表、连接线/流程图、背景图和扫描页纳入预选。Word/Excel结构预筛后，在确需图像时转换，并对转换PDF做逐页判定，共用缓存。

路径数量/形状数只作启发式预选，具体阈值用最小样本校准，不承担完整性证明。显式请求任一合法页必须允许查看；布局任务可看纯文字页；未知视觉状态不能冒充完整准备。PPT天然有页号但页图仍需渲染。

## 5. 资源合同：采用以下配置初值

以下是本方案选定的建议配置，不表示用户逐项批准或当前运行值；可用样本调整但不得以调高上限掩盖资源缺陷。

| 边界 | 初值/行为 |
|---|---|
| 通用上传 | 沿用当前50MiB默认硬上限；不把Chat能力等同上传成功 |
| Chat单文件/单轮原始大小 | 20MiB / 合计40MiB，按完整引用文件大小计，不用选择小范围绕过 |
| OOXML安全检查 | 最多10000条目、解压总量100MiB；流式计数，达到上限终止；不加载整个包到内存 |
| Chat原生结构 | 每文件最多10000块、原生提取正文最多200000字符；Excel另限制全工作簿非空单元格合计200000。单轮合计同样受10000块/200000正文字符/200000非空单元格预算约束，超限拒绝整份Chat，不静默截断 |
| PDF/PPT | 不设文件或单轮物理总页数准入上限；保留原文件大小、文字/结构、解析时间内存及每次读取限额，不默认全页栅格化 |

| OCR工作量 | 每批≤20页；同run同文件最多4次新OCR批次，重复在途/成功结果不重复计为新工作；单轮所有文件新OCR合计≤80唯一页，最多4批 |

取消物理总页数准入限制，不等于取消转换和任务工作量限制。文件页数多本身不是拒收原因；因原始大小、结构数量、转换输出或执行资源超限，仍返回准确原因。需要图形理解而视觉表示不可用，则明确视觉部分不可用，不能假装正文覆盖图形。已知超限的新附件在发模型前拒绝；run中新增工具操作失败返回稳定错误，已准备部分如实标注。Work自身受既有沙箱/上传限额，不自动接管失败Chat。

## 6. 缓存与删除

- 缓存私有绑定file_id、不可变源版本、派生器/渲染器版本及selector。不同用户不因hash相同直接共享读取权限。
- 可重建PDF/页图/预览按创建时间30天到期；旧代际脱离当前引用后24小时宽限。当前结构文字/manifest/OCR保留到文件删除或代际替换，但同样计入下面的总预算，不能无限增长。
- 全平台持久派生数据（含正文/OCR）预算1GiB。写前原子预留、流式写入不超过预留、超出则终止；发布时结算实际占用，失败/过期回收预留。可扩量必须再次准入。临时转换输出由沙箱/临时盘限额另外守住，不能拿持久预算代替临时盘控制。
- 满额先有界回收过期/可驱逐资产；活跃处理与传输租约保护，仍不足则拒绝新增派生，不删原文件/用户成品，不无条件扩容。用文件/资产登记账本和存储增量校准，避免每次读取扫描全盘；新账本的已有对象迁移需有界回填，回填未完成禁止声称预算已完全覆盖历史对象。
- 代际发布与旧资产删除意图在同一事务持久化。清理由现有reaper分批进行；删除完成才释放已占容量，失败保留意图；孤儿扫描有界补偿。
- 过期同步使元数据/行失效，下次读取重新准备。历史checkpoint本身不能永久钉住全部缓存；同字节可恢复，不同字节走显式rebuilt边界，不替换历史消息。不同文件版本不互相替代。
- 永久删除文件必须删除其所有派生前缀及对应RenderedPage/OcrPageResult/FileDerivation/DocumentBlock等行，并与并发发布做墓碑/CAS围栏，防止删完又写回。回收站到期同合同。

### 6.1 所有生成资源的所有权与回收合同（必做）

每个生成资源必须有owner（请求/job/run/文档版本/消息引用）、明确用途、状态、字节/像素预算、有效引用/租约、清理触发器和失败补偿。包括磁盘文件、对象存储、数据库行、浏览器Blob/Canvas/Worker与请求句柄；没有生命周期登记不得增加生成路径。原文件与用户成品按业务保留，不作为临时文件误删。

| 资源 | 正常释放时机 | 中断/失败与补偿 |

浏览器内存对象即时释放可达引用，不承诺JS GC即时归还OS；共享模型/字体缓存可以有明确预算并保留稳定暖基线，不能以OS RSS未立即下降单独判断泄漏，也不能用“可能GC”掩盖持续可达对象增长。

临时文件无活跃引用后的清理目标：健康环境正常路径在请求/job退出前触发完成；硬崩溃遗留按最后租约到期加15分钟宽限判孤儿，周期扫描间隔≤5分钟、批次有界，健康存储下在该截止窗口回收。实际服务/存储不可用时不能假称已删，保持可重试记录及积压年龄/字节监控，恢复后按容量与公平预算追平。该宽限只用于故障孤儿，不给正常截图滞留15分钟的许可；不得全盘无界list或误删仍在途资源。

## 7. 前缀、兼容与成本

新run采用固定新工具目录；旧run固定旧目录。文档目录、状态和读取结果仅追加消息/工具结果。等待/恢复不改已付费前缀；压缩保持现有边界合同。不把后台配置、动态文件状态放系统提示词。

旧文件有兼容结果可直接复用，无结果则首次消费懒生成；不批量重解析全库。准备、取消、模型切换、换版本及删除后的迟到回调都检查源版本和当前消费fence，不能旧结果覆盖新状态；模型切换重新准入，可复用匹配缓存，不自动重OCR。实际模式/模型变化按既有上下文边界执行，不在run内悄悄换schema或表示。

成本验收包含冷/热准备、完整回答延迟、模型往返/输入token、CPU/RSS/临时盘与持久盘；不宣称按需模式所有场景更快或调用数不增。只做必要Portal状态适配，不增加已读页数标签。

### 7.1 全链路性能与去重要求（必做）

- **服务端**：按需求解析/渲染，不为导航扫描/栅格化全部页；去除上传eager任务与浏览器成功后的后台重复转换。同file/version/selector/表示版本的在途任务合并、完成结果复用；并发写缓存CAS/容量预留，不能双算后只去重数据库行。大对象采用受限流式I/O，避免原始字节→base64→JSON→重复缓冲同时常驻；关闭HTTP/存储流与子进程组，等待deadline不占DB事务或无限持有执行槽。查询有界/索引/必要EXPLAIN，不随用户数或每次查看重扫全库。
- **浏览器**：重型解析/编码在已有Worker或可取消异步任务中进行，不在React render/频繁effect中重复执行；能Worker处理的不得阻塞主线程长任务。复用已经下载/解析的同版本文件，ArrayBuffer可转移时不复制，避免超大dataURL放组件state。页面虚拟化/懒加载，默认只维持当前页和相邻页窗口，不预渲染整份；新解码/截图任务先检查像素与缓存预算，超限不启动。建议每viewer估算解码页面缓存≤64MiB、同时重型capture≤1，普通页图/截图编码≤2MiB；分辨率按需求与设备控制，小字用局部裁剪，不盲目按高DPR全页截图。该预算是应用可控缓冲上限，非对浏览器进程总RSS的硬保证。
- **在线/离线后备**：截图按用户/源版本/页或region/分辨率合并，显式重截才产生新请求；页内视觉变化须更新表示revision，不能复用旧图。同请求多tab只执行一次；浏览器成功或后备接管后取消另一执行方，迟到结果不发布；网络分区时不能保证客户端物理计算瞬时停止，靠有效租约/本地deadline限制残留，不能把单次发布说成绝对零计算重叠。后台/隐藏页降低或暂停无需求预取和轮询，不影响已领取必要任务的可见状态/截止时间；不依赖浏览器关闭事件完成服务端清理。
- **网络与模型**：有界返回目录、片段、页图，不每轮重新传整份文件，不重复注入相同工具/技能大正文；保持前缀稳定。截图只上传需要页/region一次，服务端限尺寸/字节/像素；读授权结果与缓存版本绑定，不以省校验换性能。浏览器显示与模型实际收到分别计量。
- **维护成本**：共享parser/renderer及现有client-call，不新建等价OCR/解析栈；缓存/清理复用现有资产登记与reaper，清理本身也有CPU、I/O、批量和扫描deadline。监控标签只用低基数类型/结果，避免file/run/user标签造成监控内存增长。

### 7.2 性能与泄漏验收门槛（必须留证据）

实施开始固定测试文件、设备/浏览器、代码基线和冷/热口径；含低内存移动端、普通桌面、长PDF、复杂Office/大表格、混排、连续截图与多人争用。记录服务端CPU/RSS/临时与持久盘/执行槽/查询数/任务数，浏览器首个可交互页面与首张可用图的p50/p95、长任务、JS heap/解码缓存/Worker数量/网络字节，以及模型完整回答成本。实施前冻结各场景的延迟与内存目标；不能测试后调宽阈值通过，也不能本轮未实测先声称达标。

功能验收之外至少包括：

1. 同版本重复打开/请求不重复重型解析与转换；客户端成功后台无同请求重复render job，缓存命中无不必要模型/OCR调用；旧版本/不同region不可错误复用。
2. 预热后连续50次打开/关闭、翻页/切版本、截图/取消/超时及断线恢复；关闭并经过固定稳定观察窗口后，监听器、计时器、pending map、Worker/iframe、活跃流/进程/租约回到声明基线，临时目录/对象无残留。多轮heap快照排除仍被引用的文件/Canvas/截图增长，不能仅靠一次GC或一条健康检查判无泄漏。
3. 相同负载运行前后在途/持久资源有界；存在暖缓存时与预热后的同工作集比较，不要求所有RSS归零，但不得随已结束请求次数持续增长。发现增长须定位保留链/对象归属并修共同原因，不用扩内存、重试或周期重启掩盖。
4. 故障注入覆盖上传完绑定前崩溃、数据库/对象存储不可用、磁盘满、取消时仍在编码/推理、删除与迟到发布并发、前后端重启；最终无永久孤儿、重复job、未释放预算，清理失败确实可观察并可恢复。
5. 规范截图仍被有效消息/checkpoint引用时恢复正确；释放引用/删除后对象和数据库行清空；缓存失效重建遵守前缀/版本合同。验证清理与历史可用性两者，不以一方损坏换另一方通过。

资源边界、正常清理及崩溃补偿任何一项失败都不算完成，不以“功能能用”发布该新路径。检查和证据集中在最终代码基线，不逐小问题重复冒烟；原始heap/trace/完整日志放仓库外临时目录或CI artifact，仓库仅留必要摘要/最小复现。无证据不能声称“绝无泄漏”。

## 8. 实施与验收

顺序围绕共同原因分组，不逐问题打补丁：

1. 修统一页数/部分缓存完整性及PNG/JPEG类型事实；建立失败回归。
2. 拆安全可用与派生状态，撤普通上传自动处理；接Work原文件路径、Chat/主动预览懒准备、持久取消/恢复及限额。
