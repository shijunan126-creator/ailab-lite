# 05 实施顺序、验收与成本

[总览](README.md)。以下均为未来实施安排，本轮仅写 plan。各阶段完成只表示该阶段证据，不自动推进部署；许可/外部执行前提不满足时登记阻塞，不能删除能力行后宣称完整迁移。

## 阶段

| 阶段 | 工作及主要改动区域 | 退出条件 |
| --- | --- | --- |
| P0 来源与可执行清单 | 固定原始文件/hash/许可、逐模块/CLI/UI能力清单、依赖闭包；补查 visual delivery protocol | 来源和分发义务明确；每项能力有目标/依赖/验收；阻塞项显式列出 |
| P1 模块与上下文基础 | registry/index、prompts、load_skill、loop、checkpoint、ModelPolicy 预算接点 | 两模式可读原文模块；固定工具；轮内/跨轮/无快照压缩和恢复正确；大包不全量灌入 |
| P2 四格式制作与检查 | vendor 适配包、Office 镜像分层、原脚本/测试、runtime patch rebase、视觉评审 | 四格式创建/编辑/转换、原件保留、模板/品牌、质量检查闭环；包括 HTML/学术等重路线 |
| P3 文件/查看后端合同 | document refs、view state、fixed viewer tool、run 绑定、outbox/events、渲染/截图 | file/version/locator、离线/多端、撤权/删除、幂等和版本竞争通过；SQLite/PG迁移可升降 |
| P4 原生侧栏 | 隔离 frame/host bridge、四 viewer、选区/搜索/reveal/capture、outbox 发送 | Chat/Work 原生四格式双向联动、桌面/移动端、浅深色、关闭/切文件/stale handling 通过 |
| P5 联合与长任务验收 | recorded request、同模型效果对照、压缩/恢复矩阵、真实缓存/资源实测 | 核心矩阵通过；所有未验和阻塞能力可查；最终包/镜像/代码版本一致 |

P2 与 P3 可在 P1 合同稳定后分别推进；这里是技术依赖，不是本轮委派或实施授权。阶段不逐小改重跑全套，按阶段集中 review；产品改动的最终 Ruff、全 Python、Portal tests/build、必要浏览器/真实后端检查统一完成，只重跑失败或新增受影响检查。

## 功能与模式验收矩阵

| 场景 | 观察项/通过条件 |
| --- | --- |
| Chat 普通问答/附件全文 | 无用户沙箱；原有 prepare 完整性与预算不退化；不主动加载制作脚本或四套正文 |
| Chat 选区问答 | Word 段落、Excel 范围、PPT 对象/页、PDF 页/文字来源精确；只读必要范围，用户可点引用回看 |
| Work Word | 从零报告、公文/合同等场景、既有复杂样式修改、修订批注、目录/分节页码、表格/图片；源未改、能打开、视觉/结构验收 |
| Work Excel | 多表动态公式、原件修改、财务/分析、数据透视、图表/格式转换；输入变动后公式重算，审计抓到故意错误；VBA生成/保留与实际执行分开验 |
| Work PPT | 自由布局、原生可编辑图表、模板制作、定点改页/保样式；不强制重新套本地固定版式，容量与视觉检查能发现溢出 |
| Work PDF | ReportLab 报告、HTML海报/创意、LaTeX学术、既有PDF提取/拆合/填表/转换；字体、分页、溢出和交付完整 |
| 模板/品牌/多轮 | 用户规格/模板优先；同名新版本可继续编辑；旧 JSON/script 任务仍可恢复，原件不被覆盖 |
| Viewer 原生四格式 | 打开/目录/缩放/搜索/选区/引用/reveal/当前查看状态/capture 按能力清单逐项通过；不能用 PDF 预览替代全部原生功能 |
| UI 断线/多端/后台 | 无当前视图不猜；两个客户端不串状态；旧 ack 不覆盖新版本；无浏览器任务仍可制作/服务端检查 |
| 模型能力 | tools+vision 完整路线；tools-only 文字读取＋明确独立视觉评审；无tools维持预处理/普通回答，不假装有交互执行能力 |
| 质量门禁 | 结构、公式、内容、视觉分别有证据；脚本 exit0/WARN、视觉 pass 或生成了文件均不能单独作为完成依据 |

## 压缩、缓存、恢复矩阵

在 `tests/test_prefix_cache.py`/`prefix_harness.py` 录制请求上扩展，不用只检查最终回答代替请求结构。至少覆盖：

1. 同任务多次读同模块、多模块/多格式组合、模块分页/缺分片/错误重试；旧消息字节不变，只有必要新正文追加。
2. 轮内压缩保留正文组与丢正文组两种；丢后可重读、保留后不重复、已安装脚本仍可执行。`loaded_skills` 不能造成假“已读”。
3. 跨轮继承、父前缀压缩、无快照历史重建；保留用户原输入、文件/选区版本、交付围栏、覆盖游标和来源复验。
4. 连续至少3代强制压缩，长文档分批读完、制作/检查中途压缩；任务不失约束、无“压缩→全量补读→压缩”循环，未读范围不声称已覆盖。
5. 多工具调用成组返回、长代码块、单块放不下、auto_compact=false、小窗口；不超过硬输入预算、不出现孤立 tool result，失败可解释可恢复。
6. pending 模型/工具、文件依赖等待、QuotaPause、崩溃重启、workspace丢失、checkpoint满；不重放已确认交付和不可重放命令。
7. skill/package新版、老包缺失、镜像hash不匹配、model fallback、fork/retry/edit、撤权/删源/分享；明确边界，不静默拼版本。
8. 图片hash恢复、相同页复用、不同页新增、capture后压缩/断线、同名新版本；不把旧图当新图，不在历史里改字节省token。
9. 视觉评审主模型同形分支与独立模型分支、单批/多批/失败重试、取消和部分结果；调用计量/权限/只读约束正确。
10. 当前 GenUI、记忆刷新/recall、标题、压缩、watchdog 与新技能混用；侧调用和末尾收尾仍保持其已定义请求形状。

真实模型矩阵按 Chat/Work、调用类型、上下文段、cold/warm 分类。报告 Σcached/Σprompt（token加权）和含冷段的总值/总费用；稳定续轮目标 ≥95%，异常调用定位首个结构差异或供应商限制。分别列首轮、首次大模块加载、压缩新基底、换模型、撤权重建、TTL失效，不把它们从总账隐去。对照当前技能与迁移技能使用相同模型、输入和完成标准，同时记录成功率、用户可见错误、token/调用数和时长，不能只靠提示词更长推断质量提升。

## 性能与容量验收

目标仍为2 vCPU/~8GiB 整栈；既有 API/Broker/Worker pod 和作业限额是起点。下列为验收要求，具体绝对时延/镜像上限需 P0/P1 测量基线后在实现 PR 写定，未测前不编数值。

| 成本 | 验证方式和门槛 |
| --- | --- |
| 模型输入 | 每次实际估算 messages+tools+images 均在窗口内；模块/搜索输出按03有界；新增缓存命中 token 仍计容量；无静默正文截断 |
| 默认路径开销 | 普通Chat不启动用户沙箱/新增常驻进程；仅加载小导航，初次请求工具目录的增量可量化且仍满足既有 schema预算 |
| CPU/RSS | 冷/暖读取、LO重算、HTML/Chromium、LaTeX、截图和视觉批次分别测峰值与总时间；达到当前限额明确失败，不依靠无限重试/无限加内存 |
| 文件内存 | 服务端流式传输、临时文件有上限；原生viewer的整文件buffer明确准入，worker传输不额外复制完整文件；大文件分页回退有功能边界 |
| UI | 首屏bundle、格式lazy chunk、打开/切换/选择/reveal延迟、浏览器heap；反复开关后worker/URL/大buffer回收，无四格式全量预载 |
| 渲染复用 | 同 file_hash+render_revision+范围可复用；验收与用户预览不重复整份导出；不按每个sheet默认重启LO全量重算，批量生成后做可证明完整检查 |
| 磁盘/镜像 | 按依赖层记录压缩/解压增量；工作区、旧资源包、派生截图按引用/TTL回收；不把原始测试日志提交仓库 |
| 数据库/事件 | 文档/查看列表有界；新大表查询有索引及SQLite/PG EXPLAIN；滚动事件不进永久RunEvent；新业务副作用走事务outbox |
| 并发 | 一项重Work同时Chat文件问答仍有界推进；沿用队列/保留槽，记录排队与资源；不由单用户样例推导数百人容量 |

## 风险、未决项与完成定义

- **许可未明确**：四制作技能声明冲突、PDF/预览依赖各自条款，P0澄清后才能分发；这是实施门槛，不是要求用户现在为写plan审批。
- **原生格式保真/定位映射**：Docx/PPT/XLSX浏览器渲染与实际 Office/LO 不一定一致；以真实代表样本验收，未覆盖格式特性登记，不宣称全部Office规范兼容。
- **外部执行环境**：VBA/Windows专属功能、标准公文字体许可、LaTeX离线宏包、独立视觉模型可用性列为前提；不能默认使用用户本机账号/软件。
- **系统级上游提示词来源**：视觉角色引用的全局delivery protocol尚需定位；禁止编造一个“上游原始完整prompt”并声称原样迁移。
- **缓存目标与成本**：不能同时承诺任意调用≥95%和任意新输入；以03的结构保证和实测指标验收，长文新模块的首次成本单列。

完成须同时具备：能力清单无未说明缺项、原文/patch可追溯、三类压缩与恢复通过、Chat/Work权限不变、四格式原生侧栏双向协作、制作/检查/交付闭环、真实缓存及成本证据。已实现/本地验证/外部验收/合并/部署分别记录。
