# 03 原文模块、上下文与 Prefix Cache

[总览](README.md)。本模块是迁移的前置合同，不能先全量换入大提示词再补 token 限制。

## 资源、可见性与任务状态分开

资源身份为 `(package_id, upstream_commit, adapter_revision, module_path, content_hash, mode_profile)`。基础技能仍叫 platform.docx/xlsx/pptx/pdf；包内逻辑路径保留上游目录，不能与个人同名技能混淆。

程序分别管理：

1. **资源可用/安装状态**：某个固定包可从受控资源层读取，Work 沙箱有匹配 hash 的脚本/依赖。Chat 不需要为此租沙箱。
2. **当前可见说明**：当前 messages 中有哪些配对成功、完整且版本一致的模块正文/分片。必须根据实际消息推导，不能信任永久 loaded 标记。
3. **任务状态**：目标、源文件版本、操作计划、已完成步骤、覆盖游标、脚本/输出路径、已确认交付。由 checkpoint/业务记录维护，不依赖摘要记忆。
4. **UI 状态**：当前文档/页/选区，见[04](04-viewer-and-file-contract.md)。不能持续改写 system 或历史消息。

跨轮、轮内压缩、重启、fork 和权限变化均需重建第二类状态；第一类状态不等于模型已读说明，第三类状态也不授权重放副作用。

## 原文如何按需读取

保留完整源文件，构建时从标题/段落/代码块边界建立原文模块索引，保留源行段/hash/依赖。路由导航是单独的简短元数据，不替换原操作说明。上游已有 routes/scenes/references 直接作为模块；大 PDF/PPT 主文再按稳定章节构建模块，不把代码块或一个语义步骤切碎。

自动加载只给格式导航、必要 viewer 入口和已明确任务的最小依赖，不因四格式附件自动注入四套制作主文。用户需要新建/修改/分析时加载对应原文模块；涉及多个意图时载齐全部匹配流程、设计和质量规范。遵守上游“匹配文件完整读完”的目的：执行相关步骤前必须拥有该模块所有分片；不是遇到长文件就跳过后半部分。

候选 API：扩展 `load_skill` 支持固定的 `resource`、`cursor`、`version` 字段；保留旧 `load_skill(name)` 导航语义。读取 endpoint 在 Agent 内的受控资源层完成，Chat/Work 均可用。最终 schema 在新上下文段开始时固定，不能每加载一个模块临时加工具。

模块结果应含：资源身份、chunk_id、正文、范围、complete/next_cursor、所需依赖、安装基目录（只给 Work）。仅允许 registry 中已登记只读路径，拒绝 `..`、绝对宿主路径、symlink 和任意文件读取。禁止直接传一段用户内容当“技能路径”读取。

重复加载同一完整分片，只追加短结果和身份提示，不复放正文；部分分片只补缺少的部分。错误、被截断结果、摘要中提到“已读”、其他工具引用、未配对 tool result 都不算完成。跨分片身份必须一致，不能把新旧内容拼成“完整模块”。可见性检查只扫描消息一次并增量维护派生索引，在边界整体重建，避免每步多次扫描大历史。

## 固定前缀与升级

- system 保持模式/平台规则的稳定版本；工具目录保持顺序、schema、tool_choice 和 reasoning 同形。新模块、模板、品牌、文件变化都作为追加工具结果/消息，不修改之前字节。
- 模块和已查看页图不因换页、换选区、下一轮或 UI 刷新而重新插入。只在用户发送、模型显式读取或真正版本变化时追加。
- 包发布时新 run 冻结包版本；已有 run/待执行 tool 保持原包，相关旧包受引用保留。跨轮继续使用既有包，或显式建立升级边界后切换，不让进程重启隐式换正文。安全撤销优先，必要时拒绝旧包并重建。
- 当前四基础路径历史 checkpoint 可按旧版本继续解析；旧 JSON 规格/脚本和文件仍可编辑，不把迁移变成历史产物不可继续。新任务默认采用完整上游流程，简单生成器只作为兼容路径。
- 不修改既有工具调用来缩短参数、不删除旧图片、不把旧技能正文改为短提示；缩短只作用于新增结果。边界事件要能区分模型变化、撤权、压缩、包/工具版本重建，不能全部误报为 model_changed。

## 每次调用的预算

沿用 `ModelPolicy` 的窗口与校准估算，统一计算：固定规则＋固定 schemas＋历史＋技能原文＋用户输入＋文本/图片工具结果。缓存命中 token 仍占窗口，不能从容量中扣掉。输出按剩余窗口动态分配，并为本次任务所需最小输出及摘要指令留可估算余量；不改变现有输出分配策略为统一固定大预留。

实施初始候选：路由结果 ≤1024 估算 token；单个模块分片 ≤min(2048, 0.10×模型窗口)；读取/搜索正文每批沿用约 2000 token，实际再受剩余容量约束。这些是可测起点，不是已经证实最优值。不要固定“永久最多几个模块”；若完整任务需要更多，按边界和可重读资源推进。

加载前按 manifest 预估本分片和强制依赖，工具执行器维护同一待完成组的累计结果预算。预估不足返回明确分页/预算状态，不截断正文后声称 complete。一个 assistant 发多个 load 请求时逐结果准入，保留所有调用的配对结果；不在 tool_call 与 tool_result 中间压缩。先完成该工具组，再在合法边界压缩，随后补读。不得先产生超过硬窗口的巨大结果，再指望下一次压缩救场。

对于一个章节本身不可拆分且无法放入当前模型窗口：明确说明模型窗口不支持该路线，保留任务进度，允许用户选择更大窗口；不能丢规范、无限重读或静默换模型。小模型使用固定精简目录也必须有模块读取和必要文件工具；若无预算容纳最低合同，则明确能力不支持，而不是猜工具名绕过 allow-list。

图像准入同时受估算 token、分辨率、字节、checkpoint 大小和渲染资源限制，视觉任务按批次完整覆盖。沿用当前工作文件最多4页等已存在单次工具限制作为起点，不把它误作整任务最多4页；去重键包含文件/渲染版本、范围、detail、hash。

## 三类压缩与恢复

| 边界 | 必须保留 | 必须重算/可丢弃 |
| --- | --- | --- |
| 轮内 `_compact_work_context` | 当前原始用户输入、待确认副作用围栏、精确文件/版本/进度、近期完整工具组 | 模块可见索引按新 messages 重算；被丢正文回到可重读状态；不能沿用 loaded_skills 拒绝重读 |
| 跨轮 `_compact_parent_context` | 新一轮输入、当前/上一轮精确交付身份与任务状态，必要近期配对组 | 原文模块按实际保留情况补读，不自动恢复全部曾读模块 |
| 无快照 `_assemble_context` | 消息顺序、摘要游标/CAS、来源复验、可验证任务句柄 | 摘要不能冒充原文或安装证明；旧 UI/选区只作历史绑定，不充当当前查看状态 |
| 崩溃恢复/重投 | paid response、pending/tool invocation、non-replayable/confirmed delivery、包版本和工作区 revision | 不为重新加载说明重跑生成、交付、命令或重复付费评审 |
| fork/编辑/重试/删源 | 新分支自己的引用和状态，精确祖先范围，删除依赖围栏 | 不复用父分支活跃 UI 身份；撤权后的旧正文/截图按既有重建合同移除 |

压缩摘要调用依旧复用主请求前缀，追加摘要指令，保持同模型/工具/reasoning/tool_choice；压缩完成的下一次请求必然存在新基底冷段，显式记录。只在边界刷新资源可见性和记忆，不频繁改 system。

摘要保留任务事实和可回查句柄，不复制整份技能、全文件、截图 base64 或上游说明的摘要。摘要中的“已读模块”仅供导航，不能当规则权威。重建后只补下一步需要的模块，不把所有曾读模块再灌回；若一次补读就超过阈值，调整分片或暂停，不能压缩→全量恢复→再压缩循环。

checkpoint 容量继续独立于模型窗口：模块正文既在 messages，不能再在 checkpoint 其他字段重复保存；衍生索引只存少量身份/范围，图片使用可验证引用。满容量沿用冻结暂停，不能淘汰未确认命令记录换空间。

## 视觉评审和其他侧调用

现有 run_subtasks 不能直接承担单个只读看图评审：最少2项、工具许可和图片路径不符。计划增加固定的 artifact review 执行入口（最终工具名实施时统一），父段工具目录一次包含；单个或有界批次评审，沿用原 visual-judge 规则，输出逐页 verdict/证据，主 Agent 只修复失败项。

同模型视觉可用时，评审分支复制主请求的前缀/工具/设置并追加角色和有授权的页图，执行层收窄为只读，不通过删 schema 破坏缓存。若主模型不支持视觉，则选用平台明确配置的视觉评审模型，这属于独立模型段，单独计量和报告，不能声称与主模型共享 prefix cache；没有可用视觉模型则返回 unverified，不能伪装通过。禁止带入上游个人账号配置。

评审有 file_hash/render_revision/page_batch/brief_digest 的稳定 job 身份与状态，重试不重复确认结果，模型调用按 call_id 计费；实际供应商已接收但结果未知仍依现有 uncertain 合同，不承诺任意故障零重复付费。父上下文只接收有界逐页结论和文件句柄，不反复回灌整套页图。题目/数据真实性仍需结构/来源检查，视觉 pass 不代替内容正确。

## 缓存验收的诚实边界

必须做 recorded-request 逐字节断言和真实 cached_tokens/prompt_tokens 两种验证。稳定续轮 Chat/Work 各自累计目标 ≥95%；首轮、新模块大量正文、模型/版本切换、权限重建和压缩后的冷段分别报告，同时给出包含全部调用的总比例和费用。不能只挑高命中调用，也不能用整条消息相同推断供应商必然命中。

当新增正文占该请求超过5%时，即使旧前缀全部命中，该调用也可能达不到95%；供应商最短块、路由、TTL 同样影响比例。可保证的是前缀结构和容量合同，真实 ≥95% 是需要实测的验收目标，不能对任意短输入或每次压缩后的首调用作无条件承诺。
