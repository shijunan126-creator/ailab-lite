# 渲染沙箱生命周期与资源调度设计指南

状态：设计指导（2026-10-31，用户确认“按用户复用”）。取代 [ADR 0032](../adr/0032-prewarmed-single-use-render-sandboxes.md) 中“每个沙箱只用一次”的决定；ADR 0032 修订为指向本指南。适用于文件预览与系统解析（render 类租约）和 Work 内的 `view_workspace_file`。Work 沙箱的额度与闲置回收仍按 [ADR 0020](../adr/0020-elastic-sandbox-allowance-and-idle-reclaim.md)。

## 一、目标与约束

- 速度：上传/交付到首屏 ≤ 1.5 秒，15 页 PPTX 全页 ≤ 2.5 秒，Work 内热查看 ≤ 1 秒。
- 资源：整机 2 vCPU / 约 8 GB。render 类有独立预留（`sandbox_render_reserved_slots`、`sandbox_render_memory_bytes`，当前 1 槽 / 768 MiB），Work 不能借用，render 也不借用 Work。整机任何时刻**最多一个 LibreOffice 转换在执行**（预览、解析、工作区查看共用这一条限制），避免和 Work 抢 CPU。
- 资源最小化：无文件活动时 render 类**零常驻**；有活动时常驻数量不超过 render 槽数。所有常驻都有空闲上限和绝对寿命。
- 隔离边界是**用户**：一个渲染沙箱从创建到销毁只服务一个用户，永不换绑给另一个用户，也不退回“空闲备用”。这与 Work 沙箱的信任模型一致（同一用户的文件本来就在同一个 Work 沙箱里）。

## 二、状态机

```
creating ─▶ spare ──bind(U)──▶ busy(U) ⇄ idle(U) ─▶ releasing ─▶ gone
   │          │                    │          │
   └─失败────┴─空闲到期/让位──────┴─失败/超限┴──────▶ releasing
```

| 状态 | 含义 | 可被谁使用 |
|---|---|---|
| `creating` | 启动容器、启动常驻 LibreOffice（独立 profile、私有 pipe）、做一次极小的预热转换 | 无 |
| `spare` | 已预热，**从未接触任何用户数据**，未绑定 | 第一个到来的任意用户（绑定后不可逆） |
| `busy(U)` | 正在处理用户 U 的一个文件 | 仅该任务 |
| `idle(U)` | 已绑定 U，任务间空闲，工作目录已清空并校验为空 | 只有 U 的下一个任务 |
| `releasing` | 正在删除资源，仍计入容量直到确认删除 | 无 |

转换规则：

1. **取用（用户 U 的任务）**，依次尝试：① U 自己的 `idle(U)`；② 一个 `spare`，绑定为 U；③ 有空 render 槽则冷启动并直接绑定 U；④ 有别的用户的 `idle(V)`，立即释放（无状态，不需要快照，不需要 ADR 0020 的 300 秒保护期），然后冷启动；⑤ 全部 `busy` 时排队（见第三节）。**等待中的任务总是优先于别人的空闲温沙箱**。
2. **任务结束**：成功且健康检查通过 → 清空并校验工作目录（含 tmpfs）→ `idle(U)`。健康检查：LibreOffice 进程存活；容器 RSS 低于上限（实测后定，初值为该沙箱内存上限的 70%）；本沙箱已处理任务数 < `render_reuse_max_jobs`（初值 50）；存活时间 < `render_max_age_seconds`（初值 1800）；tmpfs 回到基线。任一不满足 → `releasing`。
3. **失败从不复用**：转换报错、超时、LibreOffice 退出、输出超限、注入失败 → 直接 `releasing`；本次任务按已有规则退回冷路径或报告失败。损坏文件很常见，代价只是下一次冷启动。
4. **空闲回收**：`idle(U)` 超过 `render_user_idle_seconds`（初值 180）释放；`spare` 超过 `render_prewarm_idle_seconds`（600）释放；任何状态超过绝对寿命释放。
5. **补充 spare**：仅当有空 render 槽、没有转换在执行、没有排队的 render 任务、最近 `render_prewarm_idle_seconds` 内有文件活动（上传、交付、Work Run 启动的提示）时，由**唯一的后台补充线程**创建；创建失败指数退避（2→60 秒），不重试风暴。`AILAB_RENDER_PREWARM=0` 时不建 spare，但同用户复用仍生效。
6. **Broker 重启或租约存储丢失**：所有 render 类租约直接释放，不认领（render 沙箱无需保留的状态）。按标签周期对账，删除没有租约记录的孤儿容器。

槽数选择：常驻 LibreOffice 实测约 274 MiB（C3f，runsc）。render 槽数与每槽内存由实测的“常驻 + 最大样本转换峰值”决定：若两个沙箱能放进 768 MiB 预留，则用 2 槽（可同时保留一个 spare 和一个 `idle(U)`，减少用户交替时的冷启动）；否则 1 槽。用数字决定并写进 ADR 0032。

## 三、调度（很多用户、资源不够时）

- **不抢占正在执行的转换**：busy 只会因超时被终止（`sandbox_render_max_ttl_seconds`）。可以被让出的只有空闲的温沙箱（`spare`、`idle(V)`），而且让出不丢任何东西。
- **优先级**（Worker 任务排序，Broker 只做槽位）：P0 Agent 正在等待的页面（`view_attachment` 等）＞ P1 用户刚上传/刚交付的首屏 ＞ P2 后台（其余页面、解析、补充 spare）。同级内**按用户轮转**，每个用户同时最多一个转换在执行；一个用户一次传 50 个文件不能饿死其他人。
- **同一用户的多个文件**优先排到该用户的 `idle(U)`/`busy(U)` 之后，而不是另开冷沙箱（热转换约 1 秒，冷启动约 3 秒）。
- **有界队列 + 截止时间**：超过队列上限或截止时间时，任务留在 Worker 的作业表中稍后重试，界面显示“生成中”，不报错；Agent 的等待有自己的截止时间并得到明确的“预览尚未就绪”结果。
- 吞吐：单机热转换约 1 文件/秒，冷约 3 秒。多机时只增加 render 槽（适配器与部署），本节规则不变。

## 四、Work 内查看（`view_workspace_file`）

- 在 Run 自己的沙箱里首次查看时**懒启动**一个常驻 LibreOffice，使用独立 profile 目录和 pipe 名，不与模型自己调用的 `soffice` 冲突；无查看 120 秒后在沙箱内自行退出；RSS 超限即终止；随租约销毁。内存计入该 Run 沙箱自己的上限。
- Work 沙箱被 ADR 0020 回收时，监听器随之消失，不留状态；下次查看冷启动。
- 文件库预览**不**复用 Work 沙箱的渲染结果：Work 沙箱由模型控制，图片可能被篡改，而库预览会展示给项目成员。

## 五、降低开销与 prefix cache

- **确定性输出**：同一内容（sha256）+ 渲染版本 → 字节完全相同的页面图片。派生结果按内容哈希缓存，只生成一次（`derived/{file_id}/`，不可变 + ETag）。模型重复查看同一文件得到相同的图片输入，追加到上下文后前缀保持不变；图片数量和分辨率有上限，不改写已有消息。
- 等待通过事件/对账唤醒，不轮询；不为预热而在没有活动时启动任何东西。
- 首屏优先：先光栅化并发布第 1 页（以及 Agent 等待的页），再发布其余页。
- 释放在结果返回之后进行，不占关键路径。

## 六、防止资源泄漏

- Broker 内存中的结构都有界并在终态清理：租约、用户绑定表、排队票据（按截止时间清扫）、活动时间、计时器。后台工作只用固定的少数线程（补充、清扫），不为每个事件开线程。
- 沙箱内：每个任务在独立工作目录，结束后删除并校验为空；tmpfs 计入内存，必须回到基线；LibreOffice RSS 与任务数、寿命共同决定回收。
- 对账：Broker 启动时释放全部 render 租约；周期按标签清理孤儿容器；`releasing` 失败按既有重试直到确认删除。
- 验证：mock 下 1000 次“绑定—使用—空闲—回收”循环后，Broker 结构大小不增长、tracemalloc 增长有界；真实 Docker 下测试结束无残留 `c3-*` 容器，空闲后 render 类内存回到零。

## 七、边界情况（每条都要有测试或明确理由）

1. 同一用户并发两个文件：第二个排在自己的沙箱后面；若有 spare 且无他人排队，可绑定第二个沙箱但每人最多 `render_max_per_user`（初值 1，2 槽时可为 2）。
2. 用户交替（A、B、A、B）在 1 槽时：每次切换都会冷启动——这是 1 槽的固有代价，用 2 槽或 spare 缓解，不能为此跨用户复用。
3. 任务中途 Worker 崩溃或连接断开：租约随超时释放，作业按 `job_id` 幂等重试；不会把未清空的沙箱标为 `idle(U)`。
4. Broker 在 `busy` 时重启：该沙箱释放，作业重试。
5. LibreOffice 卡死/崩溃：转换超时强杀并释放沙箱，本次任务退回冷路径一次，仍失败则报告失败。
6. 文件被删除、用户被禁用或失去访问权：等待中的任务取消；该用户的 `idle(U)` 立即释放。
7. 容器创建失败或 Docker 不可用：退避，不影响按需冷路径的错误报告；不产生重试风暴。
8. 内存紧张（render 预留不够放下一个新沙箱）：先释放 spare，再释放最久未用的 `idle(V)`，绝不动 busy。
9. 加密、损坏、超限文件：在注入前按大小/类型拒绝；转换失败的沙箱不复用。
10. 关闭或部署：释放全部 render 租约。
11. `AILAB_RENDER_PREWARM=0`：无 spare，其余规则不变；render 槽为 0 时预览功能按现有规则不可用。
12. 时钟：所有超时用单调时钟。

## 八、验收

三个样本（15 页 PPTX、DOCX、XLSX），每项 3 次取中位数，每次用新的文件字节：首屏、全页、按阶段拆分（扫描、排队、取用方式与耗时、注入、转换、首页光栅、首页发布、其余页、解析、导出）；同一用户第二个文件；两用户交替；两个并发上传；Work 第一次/第二次查看；空闲 spare 与 `idle(U)` 的容器 RSS、转换峰值 RSS、每次上传 CPU 秒；空闲到期后 render 类内存回到零。未达标时给出每个阶段的剩余下限及去除方法。
