## 两层压缩的统一协议

### 不变式

滚动摘要采用 `S(n+1)=Merge(S(n), Delta(cursor_n,cursor_next), pinned_state)`。输出**替换**旧摘要；原始事件仍留存。Delta包含此前未消费的完整事件/内容片段，且只有真正进入模型输入并成功提交的部分才允许推进游标。

历史压缩与本轮压缩采用同一summary schema和来源协议、不同scope和cursor，互不推进对方边界。会话只消费完成/中断后已冻结的当前分支轮次；本轮消费已经完成配对的模型/工具事件。不把未确认工具、副作用、pending交付或不可重放exec塞进摘要后删掉原始围栏。

### 结构化摘要草案

```json
{
  "schema_version": 1,
  "objective": "核对合同付款安排",
  "constraints": [{"id": "e1", "text": "只核对，不修改原文件", "sources": [{"run_id": "run_1", "part": "prompt"}]}],
  "decisions": [],
  "facts": [{"id": "e2", "text": "第8页付款条款仍待核对", "sources": [{"file_id": "fil_x", "block_id": "blk_83"}], "status": "unverified"}],
  "open_items": [{"id": "e3", "text": "确认到账日期", "sources": [{"run_id": "run_9", "part": "prompt"}]}],
  "next_actions": ["重读合同第8页"],
  "uncertainties": []
}
```

实际file/version绑定、来源digest、覆盖cursor、未完成job、delivery确认、non-replayable tool状态、plan与用户最后一次明确指令存于程序状态，独立于模型JSON。模型只能引用输入提供的来源handle；API验证存在、属于此次输入或有效旧条目、可见、版本匹配。它不能发明“处理完成”或把 `unverified` 直接变为来源已核验。

用户新的明确更正覆盖旧结论；相互矛盾的来源保留冲突与时间，不凭模型偏好解决。长期用户记忆沿用既有policy，不因压缩自动把文件全文、短期任务或被暂停的信息写入长期记忆。

### 准备、调用、提交

1. **准备短事务**：校验run attempt/branch，读取旧frame/revision和source_epoch，按token预算选连续Delta；冻结输入digest、end_cursor、source handles和每次模型call_id。提交，释放锁/数据库事务。
2. **模型调用在事务外**：显式传旧摘要、Delta、当前任务状态和不可信来源标签；输出结构化JSON。summary alias由服务端配置并验证可用性/上下文容量，不再只按最便宜weight猜质量。默认低成本文本模型；不把历史图片发送给文本摘要模型。
3. **验证输出**：schema、大小、来源handle、预算、未完成项和受程序保护的状态；新摘要不能含文件bytes/密钥。JSON无效不推进cursor；可用新call_id重试一次，随后保留旧frame、暂停或采用可容纳的原历史，不无限重试。
4. **提交短事务**：重验attempt、摘要revision、祖先链、source_epoch、来源删除和文件版本；CAS成功才插入frame、更新active指针和cursor。并发失败不覆盖，已经发生的调用仍结算一次。来源变化时丢弃候选，按新输入重新准备。
5. **装配**：当前规则＋有效摘要＋摘要之后的近期完整事件＋本轮必要文件内容；实际发送前再次预算和可见性检查。压缩失败不得把仍可恢复任务变成虚假的成功。

### 大事件、近期窗口与反复压缩失真

不再头尾截取后把整个事件记为已消费。超大工具输出先持久化到有界可重读日志对象；摘要输入为连续片段及locator，消费cursor包含 `(run_id,event_seq,part_seq)`。用户原始消息的未读部分同样不能跳过。只在part覆盖全部完成时，跨轮 `through_run_id` 才能推进。

保留近期至少2个完整工具组；已确认的本轮新用户约束不裁掉。无待总结Delta时不调用模型，摘要不能因自身较大触发“摘要再压摘要”的空转循环。达到65%B触发本轮整理，候选整理目标≤45%B；跨轮阈值设置要区分软整理与硬容量保护，`auto_compact=false`不等于允许越过硬上限。整理后仍超限则分页/暂停并保存状态。

重复摘要必然有损，采用三道保护：程序保存强制状态；条目保留可回查来源；每8次滚动更新或出现来源失效/冲突时触发一次**有界重校准**。重校准读取仍有效条目的原始依据和未完成事项，不全量扫描会话；新增预算候选≤12000token、最多一次调用，不够则分批持久进度。它不是无损保证，不得在验收中把“生成了一份摘要”等同“关键事实保真”。

程序无法仅凭规则确定任意自然语言中的全部重要约束；“强制状态”只包括用户明确的控制动作、当前原始指令及有类型的运行合同，不能虚称已确定性保存一切语义。摘要丢失旧约束仍是质量风险，需用多代回归和可回查原话降低；不能写成100%语义无损的承诺。重校准读取的原话必须遵守现有历史/记忆可见性开关。

### Fork、重试、删除与权限变化

Fork只能复用coverage完全属于其祖先路径的frame；分叉后的摘要不能带入另一支。Retry/edit supersede的旧轮次不进入新历史；本轮重新引用旧文件仍绑定原file_id。历史附件无授权、已删除或已过保留期时返回 `source_unavailable`，不自动读head版本。

删除文件/来源同事务写失效意图与epoch；异步按索引清理blocks、全文索引、派生对象和受影响frame条目。在清理完成前在线策略已拒绝读取与旧checkpoint replay。含混合来源的条目整条失效，不能留下原句只删file_id；必要时从剩余原始来源重建。正在摘要/OCR/读取的结果提交前重验，不能复活已删内容。

此处删除的是文件派生内容和相关系统摘要，不承诺自动抹除用户自己写在聊天中的独立文字或已下载副本；与既有产品删除/长期记忆合同衔接，不能擅自扩大或缩小用户选择。文件删除后不重新从历史assistant回答提炼已失效的文件内容；历史装配/摘要必须经过来源失效过滤，无法精确分离时跳过受影响派生回答并保留用户原话。


## 本地接入边界（2026-10-29）

跨轮frame每8代或有conflict条目时，API按来源权限提供最多16个/总32000字符的原文片段；Agent在摘要模型预算中计入它们，不额外开启无身份调用。片段有scope/字符范围/digest，不能当全文。当前不在预算不足时额外发起第二次校准调用；未发送的handle/offset由frame队列持久保存，下次摘要继续，按实际evidence_id前缀确认；本轮工具执行摘要仍以原始用户指令和按需原文回查为保护，不声称全部语义无损。删除采用保守的整frame失效，混合条目不保留原句。真实500轮10代质量未验。
