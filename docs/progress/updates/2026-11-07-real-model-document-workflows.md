## 观察到的问题与调整

1. **页图执行槽收尾竞态**：最后一页发布已唤醒模型，Run完成可能早于Worker最终preview完成。`file_work.finish`原先重验消费者存活，把已经返回的执行视为失权，ACK后槽仍留running/canceling，下一文件等到旧执行截止。Word实际发生111次准备轮询/122.206秒。
   修复使完成回执核验writer attempt、job claim、源版本、用户状态、执行截止，保留同事务元数据flush，但不再要求消费者仍存活。没有把所有ACK当停止，也没有放宽不确定执行的释放。新增5项隔离DB围栏回归覆盖消费者消失及stale attempt/版本/截止/禁用用户。复测Word8.891秒、3次正常准备轮询；两阶段末态重型operation均0活跃。
2. **搜索语义误用**：模型把`growth reason increase because 增长 原因`合成一个字面query，却声称逐词搜索。明确工具与生成指南的规范化字面匹配语义，并返回`query/match_mode`。400段真实模型复核遍历4批，读第351段原文；下一轮分别对growth/reason/because各遍历4批，得到1/1/0命中，无参数失败，没有把组合短语零命中当各词不存在。
3. **Work恢复绕路**：inputs不随workspace恢复；模型先运行历史build.py，遇FileNotFoundError才copy。单加系统规则后仍出现一次，因此在新追问消息旁追加API拥有的workspace恢复事实，不重写旧消息。最后一轮首个工具就是copy_library_file，然后修改/执行，0工具失败。录制请求证明Work追加该事实、Chat不混入该事实，旧前缀仍可延伸。
4. **Excel模板导入与执行反馈**：基线因只加入templates目录、使用`from base`而两次失败，且`; echo EXIT`使进程退出0，表面tool ok。V2导航和`engines/design.md`覆盖层给出技能根目录及`from templates.base`正确方式，V1包不改。补充保留真实退出码规则；观察脚本同时记录stderr Traceback/非零退出，避免只看ok。修复后没有模板导入故障，但模型仍有分号串命令的习惯，不能保证所有命令均遵守规则。
5. **范围/视觉事实与回答相关性**：指导按任务选择文字或视觉，不因unknown视觉覆盖例行渲染；不从少量页外推整文件规律。view返回实际视觉来源、页数、区域revision用法和Excel sheet→PDF页映射未知，避免native索引代际被当视觉代际。PPT指南区分业务节点与内部shape，图片中文字不能归给只含标题的文本框。定向PPT答案正确区分标题文本框与嵌图，未再错误归属；不把这个改进写成所有视觉理解绝对正确。

所有技能文字从`vendor/office-suite/build.py`生成V2覆盖层，未手改安装SKILL.md或丢弃原资源。新增`workflow_probe.py`保留有界公开API驱动、准备轮询/状态时间线、工具事件/失败、stderr诊断、回答及成品；重复工具事件可能是文件等待后的checkpoint重放，**不能直接算成重复模型决策或重复推理**。
