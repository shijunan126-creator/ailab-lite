# 资料库同名副本诊断（2026-11-03）

后续全面排查与纠正见[修复方案](../../architecture/design/2026-11-03-file-identity-repair.md)：新版已用 artifact_filename 修复新记录的名称/版本匹配，下面静态风险来自旧检出；旧元数据缺失仍可复现，不能把它推广为全部新产物仍有问题。

- 范围：只读定位用户反馈的同名编号文件与相似入口；未授权修复、清理、部署或模型复测。
- 基线：当前检出 `fix/source-pill-alignment@c033664`，与本地 origin/main 的 merge-base 为 `d7e2058`，保留既有 dirty 修改。实际服务 Compose 为 `release-3cd5a61`，比 current.md 原有部署摘要更新；已直接读取运行服务的自动交付与命名函数核对行为。
- 实证：目标会话只有一份原始 PPT。五份编号副本分别属于此前五个无 conversation_id 的后端渲染诊断 Run，事件均为 `agent.autodeliver`；另有一份改名复现 PPT，同样由诊断 Run 自动交付，SHA256 与原始 PPT 相同。历史定位入口见[渲染修复记录](2026-11-01-workspace-search-errors.md)。原始用户对话没有反复创建这些副本。
- 根因：诊断任务把文件写入 `/workspace/outputs`，虽然提示词要求不交付，`AgentLoop._deliver_leftovers` 仍在结束时收存未交付输出。独立 Run 无同会话版本父链，API 为其创建独立文件，再由 `reserve_filename` 在同用户/项目/purpose 下分配数字后缀。诊断没有隔离资料库写入并遗留产物。
- 另一路径：截图中的三份同名 PDF 为三个不同 upload_id，完整 SHA256 相同，各有不同首次消息引用；另外发现一组两份相同内容的扫描 PDF。普通上传无 parent_id 时总建新链；解析缓存只复用处理结果并生成私有副本，不复用资料库身份。现有证据不能判断每次上传由人工还是测试触发，不能称为一次请求重投。
- 静态相关风险：产物去重和同会话版本匹配使用交付前文件名，而资料库避让会改写 FileObject.filename；首次交付已被改名后，后续沿用原名可能匹配不到此前产物。该风险与本次五个独立诊断 Run 的直接原因不同，本轮未构造复现或改产品。
- 建议下一步：诊断中间件放 `/workspace/work`，真实验收采用隔离账号/项目；产品修复前明确重复上传应复用还是独立保存，并让交付身份与可变显示名分离。历史副本清理须另获授权，保留原文件与消息引用。
- 验证：只读查询 FileObject/Artifact/Run/RunEvent，核对 SHA256、上传身份、版本链和事件；内置浏览器目标页未登录，未获取凭据，页面结论以数据库证据为准。只改连续性文档，未跑 Python/Portal/build/真模型测试，未写业务数据；不声明全库无其他问题。
