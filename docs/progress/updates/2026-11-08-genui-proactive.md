# GenUI 主动使用与分档组件（2026-11-08）

分支 `feat/genui-proactive`，base `origin/main@34b1e58e`。用户反馈模型不太主动用 UI 组件、但也不希望滥用；GenUI 初始提示词放宽到约 3000 token，要求以最少 token 保持全部任务效果，并新增截图中的“左侧色块 + 右侧说明”分档样式。

## 根因

1. **判断规则按话题而不是按内容形状**：旧索引把“概念解释”列入“不用界面”，而分档、并列比较、步骤这类结构正多出现在讲解里；触发条件只写了数据趋势/对比/构成/试算。
2. **每次用组件都要先多一次工具往返**：索引只列组件名，任何组件都得先 `ui_components`，模型倾向直接写文字。
3. 主线新增的“只回答用户本次问的内容，不主动扩展”被理解为也不要把内容排成界面。

## 改动

- **索引改为“何时用 + 写法 + 规则 + 常用组件”**（Portal `catalog/prompt.ts` 生成）：按内容形状触发（用户给出或工具查到的一组数、几个并列对象/档位、步骤流程计划、选择与试算）；讲解概念时结构部分也用界面；明确“用界面呈现本次回答不算扩展”。不用界面：一两句能答完、原理解释、翻译改写成稿、代码和调试讲解、闲聊、用户要纯文字；不为讲解自造数据画图。
- **13 个常用组件的签名与注意事项直接放进系统提示**（Stack、Grid、Text、Callout、Table、Compare、Segments、Steps、Metric、Highlights、LineChart、BarChart、Series；仅 Table/Compare/Segments 保留示例）。其余组件和控件仍按需 `ui_components`；工具对常用组件返回 `already_available`，不重复正文。全量提示（无工具模型）不重复常用组件。
- **语法与决定对错的规则全部移入索引**，内置函数改为紧凑列表；工具首次返回的指南只剩交互与按钮（1886 → 276 token）。
- **新组件 `Segments`**：每类一个色块（代号、名称、关键数+单位、说明）+ 右侧标题与解释，按 tone 着色、行间分隔；复制为 Markdown 时保留同样信息。
- 平台规则版本 `2026-11-08-genui-core`；`catalog-v2.json` 增加 `core`，Python 校验常用组件含其依赖且不含 HtmlArtifact。

## 真实模型评测

模型 `deepseek-v4.1-flash`（上游 `deepseek-flash`），`evals/genui/run.py`，Chat 模式，只提供 `ui_components`。用例在原 37 场景基础上新增 8 个 `proactive`（需要结构但未提 UI）与 4 个纯文字边界（`no_ui`），共 49 场景 55 次回答。base 为同一用例在 `origin/main` 干净检出上运行。v9 为最终版去掉最后一处措辞调整前的提示词。

| 指标 | base（main） | v9 |
|---|---:|---:|
| 主动用界面（proactive） | 5/8 | **8/8** |
| 不该出 UI 却出 UI | 0/14 | 2/14 |
| 闭合块合法 | 37/37 | 48/48 |
| 显示形状错误 / 传输错误 | 0 / 0 | 0 / 0 |
| 两轮编辑结构完成 | 5/6 | 5/6 |
| 控件选择 / HtmlArtifact | 6/6、3/4 | 6/6、4/4 |
| `ui_components` 调用次数 | 39 | 23 |
| 输入 / 其中缓存 / 未缓存 | 287,480 / 173,568 / 113,912 | 347,433 / 315,008 / **32,425** |
| 输出 tokens | 107,306 | 94,685 |
| 平均延迟 | 13.65s | 11.35s |

- base 未用界面的 3 例：银行利率分层、三种数据库适用场景、安全事件分级；v9 分别用 Segments、Segments+Table、Segments+Steps。
- 中间轮 v8（Highlights 不在常用组件）出现 1 个不合法块：规则把最高/合计等结论都指向 Highlights，模型未读说明凭记忆写错签名；已把 Highlights 移入常用组件、移出 Card，v9 无此错误。v8 另有一次评测工具调用了非 `ui_components` 工具，harness 现记录 `unsupported_tool`。
- v9 的 2 例多余 UI：“天空为什么是蓝色”自行按 1/λ⁴ 算出一组数画柱图；Python 调试问题用执行轨迹表。最终版据此把触发数据限定为“用户给出或工具查到”，并把“原理解释、代码和调试讲解、不为讲解自造数据画图”写入不用界面。**该最后调整未经真实模型复测**：复测时 DeepSeek 账户返回 402 Insufficient Balance，22 个请求全部失败，未计入。
- `html-drag` 的 safe=false 是检查器把 SVG 命名空间 URI 记为 http 引用的已知误报（见评测 README）。

## 验证

- Portal：`npm test` 45 文件 270 项通过；`npm run build` 通过（第一次失败是删除的临时检查页残留 `.next/dev/types`，清空 `.next` 后通过）。
- 浏览器：临时页渲染 Segments，1280 宽深色与 375 宽浅色检查，结构与截图一致；修正了标题小于正文、单位与数字分离两处后复查。临时页已删除。
- Python：Ruff 通过；GenUI/前缀缓存/工具相关 180 项通过；评测 harness 单测通过。全套结果见下节。

## 未覆盖 / 风险

- 本轮没有重做 23 项严格数据一致性的人工判定，只做了结构检查和对主动用例、多余 UI 的逐条阅读；数据正确性规则文本未删减，只是从指南移入索引。
- 只评测 Chat；Work 模式与完整 Agent 链路未跑真实模型。
- 系统提示变化后首轮前缀缓存冷启动；随后各轮按原规则命中。
- DeepSeek 账户余额不足会同样影响使用该密钥的部署环境。
