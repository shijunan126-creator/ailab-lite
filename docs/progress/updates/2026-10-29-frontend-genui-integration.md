## 集中修复

- 工具栏的横向滚动裁剪了向上展开的技能菜单，输入框容器的层叠关系又使首页覆盖菜单。工具栏允许换行、输入停靠区保持正确层叠；320px 下模式切换不再被裁掉。还清除了迁移时留下的孤立 `.shell.collapsed` 选择器，它曾错误地把项目首页样式限定到收起侧栏时。
- 非阻塞发送保持原有上传/扫描/模型准入边界。同一毫秒发送使用单调排序；首页等待附件期间连续发送，后续消息归入首条创建的会话。已发送/删除的消息释放不再被其他待发消息引用的文件对象与上传状态；XHR 有 10 分钟超时。新增真实行为回归覆盖顺序、创建会话次数、丢失响应重试 ID/附件不变、拒绝附件不派发及释放。
- 平滑文字改为固定 120ms 的线性释放，释放结束不再申请空闲 rAF；终态/替换正文立即显示，UI 程序按块释放。新增时钟受控的行为测试。
- 复制回答在点击时调用 Markdown 转换器，避免历史页面首次渲染时 GenUI chunk 尚未加载而固定成源码。闭合的非法程序不能继续显示旧的 last-good 内容。
- 历史裁剪只对 UI 围栏整体保留/占位；普通文字超限仍保留长度限制内的前缀，不能整段丢弃。相关历史/Agent/模型上下文/会话回归 87 项通过。
- 旧队列竞态 E2E 依赖运行状态刷新整个会话；新实现只刷新 Run。测试改为持有初始会话详情，确认写入队列后才返回旧快照，继续验证真实的旧读覆盖风险，没有恢复全量轮询或删除断言。
- 上传 E2E 先放行持有的路由再 unroute，避免 Playwright 已自动处理路由后重复 continue。`npm test` 显式关闭 OpenUI Node 遥测。

## 性能与未达标项

- 在同一 HEAD 的独立源码归档与当前源码上分别新建干净 E2E 栈，500 轮加载保持顶部仅 3 轮挂载；DOM 为基线 783 / 当前 785。完整 E2E 后共享账号的侧栏已有大量会话，得到的 1199 节点不能与干净基线直接比较。
- 500 轮输入仍满足既有 `<1000ms` 断言；10 次 Playwright 输入到下一帧的最大值，基线 36.60ms、当前 48.65ms。该小样本含协议开销且并行存在浏览器任务，不构成 HLD 的 p95 ≤ 基线×1.1 验收；不宣称该项已达标。4× CPU 节流、2000 字定速流式帧时间/长任务及非流式轮次渲染计数尚未做完整基准。
- 同一版本 Next 构建清单中的 chat 路由 entryJSFiles 去重 gzip 合计：基线 61,871 B / 当前 72,443 B，增加 10,572 B；GenUI 的 createLibrary 所在 chunk 不在该 entry 清单。
- 首个 GenUI 依赖块为 80,360 B gzip（约 78.48 KiB），渲染器/目录/轻量 SVG 图表共用：**未达到 HLD 的 60 KB 目标**；没有改大预算或只计自写 wrapper。保持懒加载，后续需针对上游包图做拆分/裁剪，而非重写解析器掩盖问题。
- Node 本机热解析 15,974 字符块，20 次预热后 200 次采样 p95 0.612ms、最大 0.841ms；这是纯解析，不含 React、首次下载、浏览器布局或目标 2vCPU 容量。
- 提前预览用原 Worker 单槽、20MiB 门槛及已有渲染限额；它把成本前移，会为从不点开的文件付出 CPU/存储。首次立即点击仍可能等待，未测真实部署队列与 2vCPU 负载，不承诺冷启动零延迟。
