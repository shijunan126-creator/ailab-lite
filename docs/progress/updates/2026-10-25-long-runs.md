## 设计与实施

- 运行时长不再决定存活：Run claim 默认 300 秒，Agent 每 60 秒 token-fenced renew；过期不能复活。transport visibility 同为短租约，durable claim/attempt 是唯一执行所有权，活跃重复投递不启动第二个执行者。
- 取消 Agent 总 wall-clock wait_for；步数默认 300，token 上限保留 2M。实现活跃工作软预算/进展扩展/有界收尾、stall暂停、同job保留/新job重置窗口、本轮上下文压缩，以及 exec(background=true)/exec_wait/exec_kill。有界监督器仅通过 Broker exec 在沙箱内运行。详细决策与成本推理见 [ADR 0008](../../architecture/adr/0008-long-run-budgets-and-leases.md)。
- 不新增数据库列/迁移，复用已有 OutboxMessage claimed_until/token、checkpoint JSON 和 interrupted 手动续跑。

## 设置与 Portal 接口

环境变量均为 `AILAB_` 加以下名称的大写形式；`.env.example` 与 base manifest 的既有步数覆盖已同步。

| 设置 | 默认 | 校验 |
|---|---:|---|
| max_agent_steps | 300 | 1–10000，每个新 continuation 的模型步骤回退上限 |
| run_max_tokens | 2000000 | 正数，累计所有 attempts/continuations、review/summary/retry；不重置 |
| job_lease_seconds | 300 | 120–900；默认每60秒续租 |
| run_stall_seconds | 1200 | 601–86400，且大于 max(600, 模型单调用总截止) |
| run_soft_budget_seconds | 3600 | 60–86400，≤run_max_seconds |
| run_review_interval_seconds | 1800 | 60–86400 |
| run_max_seconds | 14400 | 60–86400，触发边界收尾，不是中途切断调用 |
| exec_background_max_jobs | 4 | 1–16，每租约并发 |
| exec_background_log_bytes | 1048576 | 4096–16777216，每后台作业环形日志 |
| run_timeout_seconds | 900（原设置） | 保留旧标题gate截止兼容；不再终止主Run/决定claim或visibility |

新增 `agent.budget`：

```json
{"kind":"soft|extended|wrap_up","minutes":60.0,"extension_minutes":30.0}
{"kind":"paused","minutes":240.0,"reason":"已工作4小时，已暂停，可继续"}
```

`minutes` 为当前窗口累计活跃分钟；`extension_minutes` 只有 extended 时为配置分钟，其余审查事件为0。paused 不含 extension_minutes。`soft` 是审查点，之后同边界发 extended 或 wrap_up。保存完成后的 paused 事件先于 pause 的 `run.status`；不会自动恢复。既有 `agent.context_compacted` 对本轮压缩新增 `{scope:"run",messages:<压缩消息数>}`；原历史轮压缩 `{turns:...}` 保留。原 `agent.tool_call`/`agent.tool_result` 事件包络不变。

工具名（Portal 需显示）：`exec`（新增 `background:true`）、`exec_wait`、`exec_kill`。后两者只在 Work 工具集中；建议中文名“等待命令”“终止命令”。

- `exec({cmd,background:true})` → `{ok,handle,running:true,output:"",total_bytes:0}`；启动非重放，仍归既有 exec。
- `exec_wait({handle,seconds:0..600,offset?:上次total_bytes})` → `{ok,handle,running,exit_code:null|整数,output:新增输出末尾最多4000字节,total_bytes,truncated,error}`。内部单次等待最多590秒，留给Broker 600秒截止清理余量；可反复轮询。stdout/stderr 合并。
- `exec_kill({handle})` → 同样结果，主动终止通常 exit_code=-9；对保留的已完成句柄幂等。wait/kill 可重放，句柄只在当前租约有效，后续启动可淘汰已完成句柄。失去句柄时 `ok:false,running:false,error:"后台命令已不存在；租约恢复后请检查工作区，勿直接重复启动"`。
- 并发拒绝 `ok:false,error:"后台命令并发数已达上限，请先等待或终止已有命令"`。命令太长则要求先写脚本再执行，避免生成的控制命令超过Broker既有20000字符限额。

暂停均为 `status=interrupted`、`resumable=true`（有checkpoint且无未答问题），`auto_resume=false`。summary、plan、artifacts 和 workspace_saved 在详情可见。用户错误文本：

- 步数：`本轮已完成 300 步，已暂停，可继续`。
- 无进展审查：`本轮暂无新的计划或文件进展，已暂停，可继续`。
- 活跃上限：`已工作4小时，已暂停，可继续`（按配置小时数格式化）。
- Stall：`长时间未收到模型或工具进展，已暂停，可继续`。
- 累计token耗尽：`本轮累计用量已达上限，已暂停；请在新任务中继续`；同Run resume 返回409 `本轮累计用量已达上限，请在新任务中继续`。这是累计成本边界，时间窗口重置不会解除。真实执行错误仍 FAILED。

人工 resume 或回答创建新 durable job，时间/步数从新窗口计；调用编号、确认交付、不可重放intent、token账本保留。没有固定人工续跑次数上限，受累计token/用户quota/并发准入/既有72小时未继续自动取消策略（ask_user_timeout_hours，终态checkpoint再保留7天）约束。恢复时注入解除旧收尾限制的提示，待pending工具结果配对后再注入。预算窗口 crash 恢复不重置；最多丢失最后一次checkpoint后的活跃时间，进程死亡时间不计工作。

## 性能与覆盖边界

- 默认每个运行中的Run每分钟新增一次claim续租：一次基于已有索引的单行UPDATE+commit；不增加每步HTTP轮询或新数据库索引。SQLite EXPLAIN 使用 `sqlite_autoindex_outbox_1 (id=?)`，PG16 使用 `ix_outbox_claim_token` Index Scan（估计1行）。已有Broker心跳/2秒取消轮询保持原样。
- 后台默认≤4个监督器、每个1MiB环形磁盘日志，控制结果≤4KB；监督器每次读取≤64KiB，持续排空输出。监督器本机macOS Python3.12空闲RSS为14768–14960KiB/个（约14.5MiB）、CPU采样0.1–0.2%，启动33.2–54.3ms；命令自身CPU/RSS另受沙箱限制。Linux沙箱/cgroup未实测，不能把该宿主值当生产保证。
- 预算只在步骤边界发起收尾，最多额外3个模型步骤和有界保存/交付操作；单个模型调用、exec/exec_wait仍有各自deadline。不会为了守wall-clock数字切断正在写文件的正常步骤。若保存失败，已有快照/dirty警告保留且 workspace_saved=false；恢复需检查工作区。
- 新回归覆盖：300默认/范围、token耗尽暂停、step暂停续跑、soft审查/有进展才扩展、旧窗口进展不买新扩展、hard保存/暂停、model/tool stall、流式进展不误判、当前Run压缩的完整tool组、续租/过期token/服务scope、续租失败停止工作、真实SIGKILL后API checkpoint重领且确认交付/后台启动不重放、wait/kill可重放、真实宿主后台进程启动/增量输出/kill/并发/日志cap/旧PID身份拒绝。
- 未做真实模型连续1–4小时、真实Linux Docker/OpenSandbox后台命令/容器内存、真实多服务Portal端到端；测试中的SIGKILL使用真实Agent/HTTP适配/API/数据库checkpoint，sandbox操作为受控fake并记录外部marker，不等于真实provider故障验收。真实sandbox恢复已有历史证据，但本轮不沿用成新后台能力的验收。
