# GenUI P6 默认模型真实评测（2026-10-30）

结论：**未通过 HLD §9 P6 全部门槛**。结构化语法、普通问答克制与控件选择表现良好；数据/上下文一致性未达 100%，失败用例唯一一次复测仍有系统性错误。没有调提示词，没有改 capability/默认开关，没有提交、push、部署或执行生成 HTML。不能据此宣称完整 GenUI 或 HTML 运行时已验收。

## 基线与方法

- 工作树 `frontend-genui`，分支 `feat/frontend-genui`，HEAD/base `97793e601d90d0e9db11d60621c4f1352450166b`，实际评测对象为当前大规模未提交树，不是该提交的干净源码。并行工程师的 Portal、后端和性能改动均保留。
- 本轮用户明确授权付费 P6；日期 2026-10-30（Asia/Hong_Kong）。配置 id `deepseek-v4.1-flash`，provider `openai`，base_url `https://api.deepseek.com`，实际请求 `upstream_model=deepseek-flash`。这是目录声明与请求别名，不推断供应商内部权重版本。
- 系统提示使用真实 `system_prompt_for(mode="chat", genui=True)`，`genui_enabled=true`、`genui_html_enabled=true`。未添加评测专用提示或替换生成目录。系统提示 10,731 字符，sha256 `ea2b6a1365502c47f509c52aeb7ae7963b9390d574605d653fdbc5d90444c1e8`；首轮单轮输入约 3,885–3,941 tokens，含用户消息。这不是 ≤2,500 tokens 目录预算已满足的证明。
- 生成目录提示 sha256 `25f0cb1e8494a6c6df45647348c1a3b8beade70cb29600be6bdf652ce5da15c5`；schema sha256 `d41205995d24e15dda315fdda7da605c9c7519d05ffe8959b31b39ca177797c4`。ADR 0028 的“HtmlArtifact 未开放”及旧交接“P6 未做”已落后于本轮实际目录与结果；本轮按当前 schema/生成提示评测，不修改这些产品决策。
- 用户提到的 `agent/llm.py` 不存在；真实实现为 `llm.py` → `model_transport.py`。runner 直接复用 `ModelTransport.chat_stream` 与 `ModelCall`，temperature **0.2**、SSE、usage、同一模型映射，无工具 schema（隔离最终回答表达能力），无 fallback/自动重试。connect 5s、read 90s、首输出 90s、total 240s，最多 3 并发，每次上限 32,768 输出 tokens，包含 reasoning；所有真实响应均正常 stop，没有打到上限。
- 两轮 case 将第一轮答案用 `for_history(keep_ui=True, limit=16000)` 作为 assistant 消息回传，与 `agent/prompts.py` 最近轮历史一致，不注入 reasoning。仅复测失败 case，两轮 case 两轮一起重跑，保留其真实生成历史；不把复测混入首轮分母。
- 37 个中文真实场景：11 个趋势/比较/排行/精确核对/整体组成，6 个试算/筛选/视图切换，4 个专门 HTML 场景（单摆、掷骰子、拖拽流程图、冒泡排序动画），10 个不应有 UI，6 个两轮编辑。**共 43 次首轮模型请求**。无 UI 类覆盖明确纯文字、单数字、翻译、改写、缺数据、已有展示不重复。每个数据场景数据内嵌；未要求用户主动点名组件的场景也包含在内。
- 密钥只从本机已有个人部署配置读入进程环境；未回显、复制或写入仓库。mock 三个响应先验证调用/历史/解析链路；随后首个受限沙箱尝试全部连接失败，未取得模型响应或 usage，不计质量和已知计费。解除网络限制后只完成一轮真实全集及一次失败子集复测（15 case / 17 请求）。

## 失败模式与代表片段

1. **语法合法不代表数据正确；正文与 UI 的计算结果互相矛盾。** 首轮 `compare-cost` 的表格表达式是 `@Round(p.cost / p.cap, 2)`，得甲24、乙23.75，但正文说“乙总支出最低但性价比最差”；复测仍称“乙单位成本最高”。首轮 `part-budget` 写“25% 对 10%”“约 1.8 倍”，实际应为 2.5 倍；`calc-discount` 把950说成原价包邮1350的“54%”，实际70.37%。
2. **已有规则未稳定约束派生值。** `lookup-price` 首轮硬写 `["M6", "0.35", "1200", "420.00"]`，算对但无表达式来源；`trend-energy` 写 `Metric("峰谷差", 95, "千瓦时")`；`calc-discount` 写 `price = $disc == "九折" ? 72 : 80`，而应由80×0.9得72。这些都能正常解析，因此只测 parser 会漏掉。
3. **表格和指标的语义不受 parser schema 保证。** `edit-top5` 首轮列名为 `["排名", "店铺", "销售额（万元）", "占全店比例（%）"]`，但每行只有 `[s.name, s.v, 占比]`，于是店名落入排名、销售额落入店铺。`trend-two` 用 `Metric("4月差额", 40, "单", 25)`，把差额从15到40的绝对增量25放入相对变化 delta。复测 `trend-energy` 又把峰值250标成“周四”，正确为周五。
4. **过度扩展分析增加错误与成本。** `compare-notwhole` 首轮引入未要求的显著性检验，写“χ²≈3.7…p≈0.16”，按输入比例计算 χ²≈7.317；复测更正此数，但声明 Wilson 区间“不重叠”，给出的82.7–95.5与67.6–82.8实际重叠。复测为静态比较额外生成 HtmlArtifact，而 Table/BarChart 足够，构成一次 HTML 滥用。
5. **HTML 检查的字面量告警需要准确解释。** 代表片段只有 `xmlns="http://www.w3.org/2000/svg"` 或 `createElementNS("http://www.w3.org/2000/svg", …)`；首轮拖拽/骰子、复测拖拽/静态置信区间图均出现。它们满足“包含 http(s)://”检查条件，但命名空间本身不发请求，不能把本结果说成发生了外部联网。没有发现 fetch/localStorage 字面量。

另有表达选择不足与冗余：`compare-delivery` 只给 Markdown 表/文字，未用目录表达；多个回答把同组数据同时放入图表、表格、指标和正文；`compare-notwhole` 首轮生成两个块。它们不直接计入四项阈值，但应作为下一版提示词收敛目标。

## 唯一一次失败子集复测

## 推荐提示词修改（本轮未实施）

1. 原句：`Use @-prefixed built-in functions (@Count, @Sum, @Avg, @Min, @Max, @Round) on data. Do NOT hardcode computed values.` 建议在最终核对规则加入：“把原数据只定义一次；所有合计、差值、单价折扣、占比、单位换算和摘要字符串中的派生数，直接引用同一表达式。例：`price = 80 * 0.9`，不写 `price = 72`；`Metric("峰谷差", @Max(values)-@Min(values), "千瓦时")`，不写95。不能表达的派生统计就省略，不手算填字面量。”仅重复现有禁止句不够，应加正反例与验算步骤。
