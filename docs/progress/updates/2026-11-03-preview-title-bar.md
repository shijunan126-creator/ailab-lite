# 预览单标题栏（2026-11-03）

- 分支 `fix/preview-header-chrome`，基线 `origin/main@3cd5a61`。用户反馈：侧栏和全屏查看器打开 Office 文件时，Portal 标题栏下面还有一条查看器自带的标题栏，两排相似图标叠在一起，文件名重复出现，首次使用看不出分别是干什么的；要求重新设计并排查其他预览位置。

## 根因

预览外壳（侧栏标签栏 / 全屏查看器顶栏）已经显示文件名、下载等文件操作；上游原生查看器在 iframe 内又画了一条 `docbar`（缩略图开关、文件名+切换菜单、查找、更多）。两层各自完整，叠在一起就成了“两条标题栏”。同类问题还有：
- iframe 的 `title` 属性在 Chromium 中会作为悬停提示出现在整页文档上（截图中幻灯片中间的第三处文件名）；Office、HTML 和网页标签都使用了它。
- HTML 文件的“渲染/源码”切换和 Work PDF 的缩放条，都在标题栏下面另起一行。
- 侧栏下载按钮是有边框的大按钮，网页标签的“在新标签打开”是文字字符 `↗`，两者与同一栏中的图标按钮不一致。

## 设计

一个预览只有一条标题栏：文件名出现一次，文件操作和文档操作都在这一行里。
- 外壳标题栏留一个 `.doc-tools` 插槽（`components/preview/doc-tools.tsx`）；预览通过 portal 把自己的文档控件放进去，不再画第二行。
- 原生查看器：构建补丁去掉上游 `docbar`；页面与目录、查找两个控件放进外壳标题栏，查看器上报哪个控件适用及是否打开（`tools`），点击发送 `command`。查找时，查找框仍出现在文档顶部，Esc 关闭。文件切换菜单与 Portal 标签重复，随之去掉；“更多”菜单里的适应宽度和缩放仍可通过底部页码控件与 ⌘0/⌘± 使用，“适合页面/实际大小/重新加载”不再提供。
- 全屏查看器：`文件名 · 版本 …… 页面与目录 查找 | 对话 分享 下载 关闭`，用细分隔线区分文档控件和文件操作。
- HTML“渲染/源码”改成标题栏里的分段控件；Work PDF 的页数与缩放改成浮在页面底部的胶囊，与原生查看器的页码控件一致。
- 所有预览 iframe 改用 `aria-label`，不再出现悬停提示；侧栏下载、在新标签打开统一为图标按钮。
