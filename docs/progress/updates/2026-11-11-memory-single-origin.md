# 记忆只有一种行（2026-11-11）

分支 `feat/memory-single-origin`，base `main@2a29fffe`。决定见 [ADR 0037](../../architecture/adr/0037-memory-single-origin.md)。

## 做了什么

- 去掉受保护/推断/待确认/暂停：origin 一律 `memory`，status 只剩 active/closed；页面去掉“你添加的”“推断”标签、“确认无误”和待确认区。
- 敏感内容照常记；证件号、银行卡号、凭据在 guard 拒绝。
- 按新标准整理一次时可拆分混合行（`add` + `from`）；标准新增“一行一个分类、事实与由它带来的做法分开写”。
- 迁移 0069、ABI 7、`PROMPT_VERSION=2026-11-11`。

## 验证

本地（代码基线为本分支工作树）：`ruff check`/`format --check` 通过；记忆相关、前缀、上下文、迁移（含 0069 升降级）、agent loop 定向测试 SQLite 全部通过；Portal `memory-view` 10 项、tsc 通过。完整双库、E2E、Portal build 交 CI。

真实模型（deepseek-flash，合成数据，`/tmp` 临时脚本，已删除）：

| 场景 | 结果 |
|---|---|
| 一次性整理 | 把“关注美股科技公司财报，偏好以丰富可视化方式呈现”拆成兴趣 + 偏好两行，其他行不动 |
| 日常批次（6 段对话） | 记下表格偏好、糖尿病、基督徒；身份证号和一次性翻译不记；项目上线转为过去式并新增现状。调整提示词前“基督徒，周日上午不安排会议”混成一行，调整后拆为事实 + 偏好 |
| 记忆页对话框（5 条指令） | 新增、拆分、换工作（过去式 + 现状）、删除均正确；“忘记华为那条”改写为去掉华为的一行并在回复中说明 |
| 对话工具（Chat 5 轮） | 记住→add explicit；换工作→replace 过去式 + add；忘记→remove；无关问题不动记忆；健康→事实 + 偏好两行 |
| 前缀缓存（同一次对话测得） | 首调用后 9 次调用 cached/prompt = 97.4%，逐调用只增不改 |

真实库副本（本机测试环境数据库的只读快照，用后删除）：0069 升/降/升各 <0.3 秒，11 条活动行 origin 改为 memory，19 条关闭历史不动，完整性检查通过（该库已无待确认/暂停行，这一分支只由合成迁移测试覆盖）。浏览器打开记忆页：无“你添加的/推断/确认无误/待确认”。点「立即整理」（真实模型）：混合行拆成“关注美股与科技公司财报（英伟达、英特尔、奈飞）”+ 偏好“看数据时希望以丰富的可视化方式呈现”（保留 5 段对话来源），中概与昇腾两条兴趣合并，一段新对话新增 1 条，记录 `prompt_version=2026-11-11`。

由此发现：一条链的后继批次在 `_finish` 时丢掉了前序批次计数（`*_before`），页面只显示最后一批（“看了 1 段对话，新增 1 条”，漏掉整理）。根因修复：`CHAIN_KEYS` 保留这三个计数；页面提示同时写新增和整理条数。

对话工具多一次 list：规则改为“快照、更新块和工具结果就是当前文档，要改的行在其中时直接 replace/remove；找不到或行已变化才 list”。服务端本就拒绝失效 handle 并提示先 list，每轮开头也会对已见过的行补发失效通知，所以直接改是安全的。复测 5 轮（记住/换工作/忘记/改本对话新增的行/问不存在的记忆）：前四轮都直接改、无 list；最后一轮查历史后如实说没有。11 次模型调用，warm 缓存 98.9%，逐请求只追加。

记忆页对话框和整理各自是单次调用，相邻调用相隔数秒，供应商未命中缓存（cached=0）；它们的系统提示在前、数据在后，前缀结构稳定。
