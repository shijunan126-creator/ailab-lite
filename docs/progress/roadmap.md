# 开发路线图

这里只列尚未完成的目标、验收标准和先后顺序。已经实现的能力见 [status-matrix](../architecture/status-matrix.md)，当前进行中的工作见 [current](current.md)。

**计划不等于授权实施。** 每一项都要在开始时由当次任务明确范围、分支、是否提 PR 和是否部署；前一阶段的授权不延续到下一项。

## 顺序与依赖

1. **单机目标机容量与长期稳定性**：在 2 vCPU / 约 8 GiB 的完整五服务栈上测混合负载、长会话、文件处理与回收。
   - 验收：记录首字/排队/outbox/未对账延迟，各 Pod CPU、RSS、磁盘与限额；连续运行后 Broker 结构、render 类内存和临时文件回到基线；不以单轮通过或单机开发数据代替容量结论。
   - 依赖：Agent、Broker、Worker、Portal 当前实现。
2. **外部依赖的真实环境验收**：企业 IdP、真实付费模型、S3、OpenSandbox/runc、k3s IPv6/多 CNI。
   - 验收：每项记录真实后端版本与网络拓扑；登录、模型调用、对象读写、沙箱创建/恢复、签名重载和故障恢复有可复现证据；缺凭据或硬件的项明确写未覆盖。
   - 依赖：部署方提供账号、硬件和网络。
3. **多节点 Broker 路由与扩机**：把单机 Broker 的所有权、租约和准入扩展到多实例。
   - 验收：业务授权、账本、文件交付和 Portal 事件协议不变，只替换 adapter 与部署；跨节点路由、故障接管、容量隔离和重复投递收敛有契约测试；单机路径仍可用。
   - 依赖：第 1 项的容量基线和第 2 项的 k3s/OpenSandbox 结论。
4. **部门额度池与软硬水位**：在现有用户/部门策略之上增加份额和水位。
   - 验收：部门份额、软/硬水位、跨部门借还与告警有明确语义；并发预留不越界；历史用量仍读冻结的账本与部门快照。
   - 依赖：第 3 项的调度边界；未定产品语义前不实现（ADR 0020 明确当前不含）。
5. **备份与灾难恢复**：从逻辑备份推进到持续归档、异地介质和明确 RPO/RTO。
   - 验收：数据库与对象清单可恢复到空环境；恢复后新 API 下载、预览和 Run 通过；停写窗口、GC 协调、失败重试和演练记录齐全。
   - 依赖：第 1 项的存储基线。
6. **质量门槛与业务评测**：记忆整理质量、GenUI 真实模型正确性、办公技能业务 golden。
   - 验收：使用真实对话/文档与真实模型，记录逐条失败和缓存证据；不以合成样本或测试通过数代替业务质量。
   - 依赖：用户提供公司模板、业务样本和评测口径。

## 不在当前范围

- 多租户分片、跨区域部署和分布式事件总线；单机与后续多节点都沿用现有业务合同，除非另写 ADR。
- 按角色的部门份额分级、预热池和跨用户沙箱复用；见 [ADR 0020](../architecture/adr/0020-elastic-sandbox-allowance-and-idle-reclaim.md) 与 [ADR 0001](../architecture/adr/0001-single-node-scope.md)。
- 没有明确验收标准的新框架、新数据库或新 UI 依赖。
